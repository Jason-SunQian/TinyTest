# 物料配置与未来架构说明

> 本文档澄清：设计器与插件间的物料传递协议、为何不应使用 settings.json、目标架构（ASSETMANAGER UI → 设计器），以及主工程 `dist/lowcode-materials` 产出物要求。

---

## 一、设计器需要什么（协议不变）

设计器**只接收一种数据**：**bundle.json 的 URL 数组**，类型为 `string[]`。

```typescript
// 设计器读取的接口（注入到 window 或通过 getInitData）
window.TINY_MATERIAL_BUNDLE_URLS = [
  "https://xxx/bundle.json",   // 可访问的 bundle.json 地址
  "http://localhost:3456/bundle.json"
];
```

设计器会：

1. 请求每个 URL 得到 bundle.json
2. 解析其中的 `components`、`snippets`、`blocks`、`runtimeScript`
3. 在物料面板展示组件、支持拖拽
4. 从 bundle 中加载组件脚本和样式
5. 若有 `runtimeScript`，优先加载主工程的 runtime 桩

**设计器不关心**：这些 URL 从哪来、是本地 serve 还是私服 npm、用户怎么配置的。它只要「可访问的 bundle.json URL 列表」。

---

## 二、为何不用 settings.json

`settings.json` 是 VSCode 的**工作区/用户偏好配置**，适合放：

- 格式化、Lint、i18n 等**开发体验**相关配置
- 与具体项目**运行时数据**无关的设定

物料包是**项目级资产**：

- 不同项目用不同的物料（主工程 A、主工程 B、私服包…）
- 应在**项目内**管理，而不是散落在「用户设置」里
- 用户期望在**界面上**导入/配置，而不是手写 JSON

因此：**物料配置不应放在 `settings.json`**。插件已移除 `lowcode-designer.materialBundleUrls` 配置项；物料 URL 将由 ASSETMANAGER + lowcode.config.json 注入，与 settings.json 无关。

## 三、目标架构：ASSETMANAGER UI 驱动

### 3.1 用户视角

用户在插件侧栏 **ASSETMANAGER** 中：

| 操作 | 含义 |
|------|------|
| **导入本地物料包** | 选择项目下的 `dist/lowcode-materials` 等目录，或主工程构建产物路径 |
| **添加私服 npm 物料** | 输入 `@company/lowcode-materials@1.0.0` 等，由插件从私服安装并解析 |

**无硬编码 URL**：用户不写 `http://localhost:3000/bundle.json`，只选路径或填包名。

### 3.2 插件职责（需在 lowcode-kit 中实现）

```
ASSETMANAGER UI
    │
    ├── 本地路径：用户选择 dist/lowcode-materials
    │       → 插件启动/复用静态服务，得到可访问 URL
    │       → 如 http://localhost:3456/bundle.json
    │
    └── 私服 npm：用户输入 @company/xxx@1.0.0
            → 插件 pnpm install 到临时目录
            → 找到约定目录（如 dist/ 或 package.json 的 exports）
            → 启动静态服务
            → 得到 http://localhost:xxxx/bundle.json
    │
    ▼
存储到项目配置（如 lowcode.config.json 或 workspace 专用存储）
    │
    ▼
打开设计器 webview 时
    → 读取当前物料列表
    → 解析为「可访问的 bundle.json URL 数组」
    → 注入 window.TINY_MATERIAL_BUNDLE_URLS = [...]
```

### 3.3 传给设计器的「值」

**始终是**：可访问的 `bundle.json` URL 数组。

| 用户操作 | 插件解析结果 | 注入给设计器 |
|----------|--------------|--------------|
| 选择 `./dist/lowcode-materials` | serve 后得到 `http://localhost:3456/bundle.json` | `["http://localhost:3456/bundle.json"]` |
| 添加 `@company/lowcode-materials@1.0.0` | 安装 + serve 得到 URL | 追加到数组 |
| 多个物料源 | 多个 URL | `["url1", "url2", ...]` |

**设计器侧**：收到 `window.TINY_MATERIAL_BUNDLE_URLS` 后，拉取各 bundle、合并组件、更新物料面板，逻辑已支持（见「四、设计器侧改造」）。

### 3.4 项目级配置建议

物料列表建议落在**项目内**，例如：

- `lowcode.config.json`（项目根目录）
- 或 `.lowcode/materials.json`

示例：

```json
{
  "materials": [
    { "type": "local", "path": "./dist/lowcode-materials" },
    { "type": "npm", "package": "@company/lowcode-materials@1.0.0" }
  ]
}
```

插件读取此配置，解析为 URL 后注入设计器，而不是读 `settings.json`。

## 四、设计器如何接收并展示插件传入的物料

### 4.1 接收方式：注入而非消息

插件**不通过 postMessage** 传递物料，而是在打开 webview 时，在 HTML 中**注入一段脚本**：

```html
<script>window.TINY_MATERIAL_BUNDLE_URLS = ["http://localhost:3456/bundle.json"];</script>
```

设计器加载时，这段脚本已执行完毕，`window.TINY_MATERIAL_BUNDLE_URLS` 已就绪。设计器只是**读取**这个全局变量，不涉及「接收消息」。

### 4.2 完整调用链（按执行顺序）

| 步骤 | 文件 | 逻辑 |
|------|------|------|
| 1 | `packages/design-core/src/App.vue` | `watch(isCanvasApiReady)` → 画布就绪后调用 |
| 2 | `designer-demo/src/plugins/materials/composable/useResource.ts` | `fetchResource()` → `useMaterial().fetchMaterial()` |
| 3 | `designer-demo/src/plugins/materials/composable/useMaterial.ts` | `fetchMaterial()` → `getBundleUrls()` 获取 URL 列表 |
| 4 | `designer-demo/src/composable/loadRuntimeFromBundles.ts` | `getBundleUrls()` 读取 `window.TINY_MATERIAL_BUNDLE_URLS`，并与 engine.config、env 合并 |
| 5 | `useMaterial.ts` | `getMaterialsRes()` 对每个 URL 执行 `Http.get(url)` 拉取 bundle.json |
| 6 | `useMaterial.ts` | `addMaterials(materialsPayload, bundleUrl)` 解析 components、snippets、blocks |
| 7 | `useMaterial.ts` | `addComponents()` / `addBlocks()` 写入 `materialState.components`、`materialState.blocks` |
| 8 | `designer-demo/src/plugins/materials/meta/component/src/Main.vue` | 通过 `useMaterial().materialState`、`getComponentsByGroup()` 展示物料面板 |
| 9 | 画布 | `updateCanvasDeps()` 更新画布依赖，拖拽时按 `npm.script` 动态加载组件 |

### 4.3 关键代码位置

| 环节 | 文件路径 | 行号/函数 |
|------|----------|-----------|
| 读取插件注入的 URL | `src/composable/loadRuntimeFromBundles.ts` | `getBundleUrls()` 第 22-26 行，读 `window.TINY_MATERIAL_BUNDLE_URLS` |
| 拉取 bundle | `src/plugins/materials/composable/useMaterial.ts` | `getMaterialsRes()` 第 796 行，`fetchMaterial()` 第 809 行 |
| 解析并写入物料状态 | `src/plugins/materials/composable/useMaterial.ts` | `addMaterials()` 第 761 行，`addComponents()` 第 700 行 |
| 物料面板展示 | `src/plugins/materials/meta/component/src/Main.vue` | 第 96 行 `materialState`，第 110 行 `componentsWithChildren` |

### 4.4 设计器侧改造（已完成）

设计器已支持「合并多种来源的 bundle URL」：

- `engine.config.material`（内置物料）
- `window.TINY_MATERIAL_BUNDLE_URLS`（**插件注入**，未来由 ASSETMANAGER 解析得到）
- `VITE_MATERIAL_BUNDLE_URLS`（非插件本地调试）

`getMaterialsRes` / `fetchMaterial` 使用 `getBundleUrls()` 统一获取上述列表，物料面板会展示所有来源的组件。

### 4.5 与 ASSETMANAGER 的衔接

| 环节 | 插件当前实现（调试用） | 目标：ASSETMANAGER |
|------|------------------------|--------------------|
| URL 来源 | 已移除（原 settings.json 方式已删除） | 用户在 ASSETMANAGER 界面**动态**添加（选本地路径、填 npm 包），插件解析为 URL 并注入 |
| 存储位置 | settings.json（静态配置文件） | 项目配置（如 lowcode.config.json）或工作区状态，**不涉及 settings.json** |
| 设计器接收 | 读 `window.TINY_MATERIAL_BUNDLE_URLS` | 不变 |
| 设计器行为 | 拉取 URL、展示物料、支持拖拽 | 不变 |

**区分**：ASSETMANAGER 的物料导入是**动态操作**（用户点「添加」→ 选路径/填包名 → 立即生效），与 settings.json 这种**静态配置**（需手动编辑 JSON、与 IDE 偏好混在一起）无关。设计器协议不变，改造重点在**插件的 ASSETMANAGER UI 与解析逻辑**。

| 配置 | 建议 |

## 七、主工程 `dist/lowcode-materials` 产出物

### 7.1 结构

```
dist/lowcode-materials/
├── bundle.json          # 物料 manifest，符合 TinyEngine 协议
├── mr-components.js     # 原子组件入口
├── mp-*.js              # 业务组件 ESM
├── mr-bank.css          # 设计 token + base 样式
├── __theme__.js         # 主题相关（若有）
└── runtime.js           # 可选，bundle.json 中 runtimeScript 指向
```

### 7.2 是否满足要求

**是的，`dist/lowcode-materials` 即为所需产物**，满足：

1. **bundle.json**：含 `components`、`snippets`、`runtimeScript`（若有）等，符合 TinyEngine 物料协议
2. **ESM 脚本**：组件为 ESM，画布通过 `import(scriptUrl)` 动态加载
3. **样式**：`mr-bank.css` 或各组件的 `npm.css`，画布会按需加载
4. **runtime**：主工程若在 bundle.json 中声明 `runtimeScript`，设计器会优先加载该 runtime

### 7.3 与 ASSETMANAGER 的衔接

| 场景 | 做法 |
|------|------|
| **ASSETMANAGER 导入本地** | 用户选择 `dist/lowcode-materials` → 插件 serve 该目录 → 得到 `http://localhost:xxxx/bundle.json` → 注入 |
| **ASSETMANAGER 添加私服 npm** | 用户输入 `@company/lowcode-materials@1.0.0` → 插件安装并 serve → 得到 URL → 注入 |
| **非插件本地调试** | 主工程 serve 后，在 env 中配置 `VITE_MATERIAL_BUNDLE_URLS` 传入 |

### 8.1 插件侧改造实现指引（待实现时参考）

以下分两条链路说明：**写入**（ASSETMANAGER → lowcode.config.json）和**读取并注入**（打开设计器时 → 解析 → 注入）。

---

#### 一、物料列表存 lowcode.config.json（写入链路）

**目标**：用户在 ASSETMANAGER 中添加物料后，将配置持久化到项目根目录的 `lowcode.config.json`，替代 settings.json。

**配置格式示例**：

```json
{
  "materials": [
    { "type": "local", "path": "./dist/lowcode-materials", "label": "主工程物料" },
    { "type": "npm", "package": "@company/lowcode-materials@1.0.0", "label": "私服物料包" }
  ]
}
```

**实现步骤**：

1. **新建读取/写入工具**（如 `packages/vscode/src/services/materialConfigService.ts`）：
   - `getMaterialConfigPath()`：返回工作区根目录下的 `lowcode.config.json` 路径
   - `readMaterialConfig()`：读取并解析 JSON，返回 `{ materials: MaterialEntry[] }`
   - `writeMaterialConfig(config)`：将配置写回文件
   - 若文件不存在，`readMaterialConfig` 返回默认 `{ materials: [] }`

2. **ASSETMANAGER UI 添加物料时**：
   - 用户点击「导入本地」→ 弹窗选择目录（如 `dist/lowcode-materials`）→ 得到 `{ type: "local", path: "..." }`
   - 用户点击「添加 npm」→ 输入包名版本 → 得到 `{ type: "npm", package: "..." }`
   - 调用 `readMaterialConfig()` 获取当前列表，追加新项，再调用 `writeMaterialConfig()` 写入

3. **删除/编辑**：ASSETMANAGER 提供删除、修改能力，同样通过 `readMaterialConfig` + `writeMaterialConfig` 更新文件。

**涉及文件**：ASSETMANAGER 视图的 Provider、TreeView 或 Webview，以及上述 `materialConfigService.ts`。

---

#### 二、解析路径/npm → URL 并注入（读取并注入链路）

**目标**：打开设计器 webview 时，从 `lowcode.config.json` 读取物料列表，将每条解析为**可访问的 bundle.json URL**，注入 `window.TINY_MATERIAL_BUNDLE_URLS`。

**实现步骤**：

1. **解析逻辑**（如 `packages/vscode/src/services/materialUrlResolver.ts`）：
   - 输入：`MaterialEntry[]`（来自 lowcode.config.json）
   - 输出：`string[]`（bundle.json 的绝对 URL 列表）

   - **type: "local"**：
     - 将 `path` 解析为绝对路径（基于工作区根目录）
     - 检查目录下是否存在 `bundle.json`
     - 若存在：启动或复用静态服务（如 `serve`、`http-server`），得到 `http://localhost:PORT/bundle.json`
     - 端口分配：可用端口池（如 3456、3457…），避免冲突
   - **type: "npm"**：
     - 在工作区或插件的临时目录执行 `pnpm add @company/lowcode-materials@1.0.0`（或 npm）
     - 在 `node_modules/xxx` 下找到约定目录（如 `dist`、`lowcode-materials`）
     - 对该目录启动静态服务，得到 URL

2. **注入时机**：在 `designerWebviewService.ts` 中，构建 HTML 之前：
   - 调用 `readMaterialConfig()` 获取物料列表
   - 调用 `resolveMaterialUrls(entries)` 得到 URL 数组
   - 若有 URL，生成注入脚本：`<script>window.TINY_MATERIAL_BUNDLE_URLS = ${JSON.stringify(urls)};</script>`
   - 与现有逻辑一致，在 `</body>` 前插入

3. **当前状态**：插件已移除对 settings.json 的读取；`window.TINY_MATERIAL_BUNDLE_URLS` 暂不注入，待 ASSETMANAGER + lowcode.config.json 实现后从该流程注入。

**涉及文件**：`designerWebviewService.ts`（生产模式、开发模式两处）、新建 `materialConfigService.ts`、`materialUrlResolver.ts`。

---

#### 三、改造顺序建议

1. 先实现 **materialConfigService**（读写 lowcode.config.json）
2. 再实现 **materialUrlResolver**（解析 local/npm → URL），可先只支持 `type: "local"`（路径已存在且可 serve）
3. 修改 **designerWebviewService**：在构建 HTML 时调用 materialUrlResolver，将解析得到的 URL 注入（原 `getConfiguration('materialBundleUrls')` 已删除）
4. 最后实现 **ASSETMANAGER UI**：添加/删除物料时调用 materialConfigService 写入

## 九、总结

- **设计器协议**：只接收 `window.TINY_MATERIAL_BUNDLE_URLS`（bundle.json URL 数组），不关心来源。
- **不用 settings.json**：物料应在 ASSETMANAGER UI + 项目配置（如 lowcode.config.json）中管理。
- **设计器侧**：已支持读取 `window.TINY_MATERIAL_BUNDLE_URLS`，插件只要注入 URL 数组即可。
- **插件侧待做**：ASSETMANAGER UI（导入本地/私服 npm）→ 解析为 URL → 注入设计器。
