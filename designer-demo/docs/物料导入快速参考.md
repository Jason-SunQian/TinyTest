# 物料导入快速参考

> 本文档整理设计器如何从主工程导入物料资产包，供后续改造与维护时快速查阅。  
> 适用于：理解当前架构、排查问题、规划物料导入改造（降低维护成本、提升可扩展性）。

---

## 二、物料资产包协议（核心字段）

### 2.1 顶层结构

```json
{
  "data": {
    "framework": "Vue",
    "materials": {
      "components": [],   // 组件列表
      "snippets": [],     // 物料面板分组与展示
      "blocks": []        // 区块列表（可选）
    }
  }
}
```

### 2.2 组件配置（components）

| 字段 | 类型 | 说明 |
|------|------|------|
| `component` | String | 画布渲染时的组件名，对应 Vue 组件名 |
| `group` | String | 分组（如「原子组件」「业务组件」） |
| `npm.package` | String | 包名或占位符（如 `@local/mp-card`） |
| `npm.script` | String | 脚本 URL，**必须是 ESM**，画布通过 `import(script)` 加载 |
| `npm.exportName` | String | 导出名（如 `MpCard`） |
| `npm.css` | String | 样式 URL（可选） |
| `schema` | Object | 属性 properties、事件 events、插槽 slots |
| `icon` | String | 物料面板图标名 |

### 2.3 物料面板配置（snippets）

- `group`：折叠面板标题
- `children[].snippetName`：对应 `components` 中的 `component`
- `children[].schema`：拖入画布时的默认 schema

### 2.4 必守规则（本工程约定）

- **图标**：物料需配置 `icon` 或使用默认 `component-default`
- **分组**：`group` 使用 `"原子组件"` / `"业务组件"`，英文由设计器自动翻译
- **名称**：`name` 必须包含 `zh_CN` 与 `en_US`

## 三、原子组件（mr-*）与业务组件（mp-*）

### 3.1 原子组件

- **来源**：Vant + Ionic（@mr/wise-core），主工程有样式覆盖
- **统一入口**：`entries/mr-components.js`，按主工程 resolver 命名 re-export
- **策略**：
  - Vant 原子：直接 re-export
  - Ionic 原子（如 MrImg）：可做设计态占位（无 src 时显示占位，有 src 渲染真实组件）
  - Ionic 原子（Shadow DOM）：用画布桩 + 样式自注入（MrSegment、MrSegmentButton、MrLabel）

### 3.2 业务组件

- **简单组件**：直接引用主工程源码（如 `mp-card.js` → `import MpCard from '../../src/components/mp-card.vue'`）
- **复杂组件**：使用设计时兼容版或画布桩（画布桩可有效规避重依赖、保持物料轻量）
  - `design-components/mp-input-designer.vue`：用 MrField 替代 ion-input
  - `canvas-stubs/components/mp-account-input-canvas.vue`：画布桩，保留结构替换复杂子组件
- **组件内用 $t 的**：若画布显示 i18n key 而非译文，需做 canvas 桩并在桩内 `import { t as $t } from '../vue-i18n'`，在 canvas-stubs/vue-i18n.ts 的 FALLBACK 中补充 key（如 MpAgreementButton、MpAccountInput）
- **重依赖组件**（vue-pdf-embed、pdf.js、复杂图表等）：做 canvas 桩占位，避免 chunk 膨胀与 worker 配置问题（如 MpPdf）

### 3.3 依赖关系

- 业务组件依赖原子组件，构建时 `@local/mr-components` 为 external，由设计器画布提供
- 画布需注入 Vant、Ionic 的脚本与样式，以及主工程提取的 design-tokens、base-overrides

## 四、设计器侧物料加载流程

1. **配置物料源**：`engine.config.material` 数组，支持多 bundle
2. **拉取**：`getMaterialsRes()` 请求各 URL，合并 `components`、`snippets`
3. **注册**：`addMaterials()` 写入 `materialState`
4. **画布依赖**：`getCanvasDeps()` 组装 scripts/styles，`updateCanvasDeps()` 通知画布更新 import map
5. **拖拽渲染**：画布通过 `npm.script` 的 URL 做 `import(script)` 动态加载组件

### 4.1 环境变量与注入

- `VITE_EXTRA_MATERIAL_BUNDLE_URL`：开发时额外 bundle URL
- `VITE_MATERIAL_BUNDLE_URLS`：逗号分隔的多个 URL
- `window.TINY_MATERIAL_BUNDLE_URLS`：VSCode 插件注入
- URL 参数：`?materialBundle=...` 或 `?materialBundles=...`

## 五、主工程新增组件流程（当前）

### 5.1 新增原子组件（mr-*）

1. 在 `entries/mr-components.js` 中增加 re-export（Vant/Ionic/桩）
2. 在 `manifest.json` 的 `components` 中增加一条
3. 若为 Ionic 桩，在 `canvas-stubs/components/` 下实现
4. **若组件内容在 slot 中**（如 MrLabel、MrButton）：schemaExtra 用 `property: "children"` + InputConfigurator（单行输入），并设置 snippetSchema 默认 children；否则运行时不显示（详见《Ionic组件导入与桩方案》2.6 节）
5. **属性选项一律展示英文**：SelectConfigurator 等 options 的 label 用英文（如 Default、Primary、Large），项目规定
6. **画布桩必须可见**：桩样式设 `min-height`，slot 提供默认内容（如 `Loading...`），确保拖入后画布始终有占位，便于定位
7. **事件不写进 snippet**：snippetSchema.props 只含属性默认，不含事件 handler，否则会覆盖用户绑定；事件在 schemaExtra.events 声明，由用户在「高级」→「事件绑定」中配置
8. **事件方法注释**：若事件 handler 需调用特定 API（如 `evt.target.complete()`），可在 BindEventsDialog 的 rewriteMethodParams 中，按 eventName 注入带注释的默认方法体

### 5.2 新增业务组件（mp-*）

1. 在 `entries/` 下新增 `mp-xxx.js` 入口
2. 在 `manifest.json` 中增加物料配置
3. 若需设计时版：在 `design-components/` 或 `canvas-stubs/components/` 下实现
4. 若需样式提取：在 `extract-canvas-styles.cjs` 的 `STYLE_CONFIG` 中配置

### 5.3 导入顺序

先保证 mr-* 可用，再接入依赖它们的 mp-*。

## 六、当前痛点与可改造方向（待后续尝试）

| 痛点 | 现状 | 可改造方向 |
|------|------|------------|
| **manifest 冗长** | 每个组件一条完整 JSON，schemaExtra 重复、难维护 | 按组件拆分 JSON + 脚本合并；或 schema 从组件源码/类型推导 |
| **多入口分散** | 每个组件一个 entry 文件，新增需改多处 | 单入口 + 动态注册；或脚本根据 manifest 自动生成 entries |
| **样式提取繁琐** | 多个 extract 脚本，需手动配置 STYLE_CONFIG、ASSET_CONFIG | 统一提取流水线；或约定目录结构自动发现 |
| **Ionic 桩维护** | 每个 Ionic 组件需单独桩 + 样式自注入 | 通用 Ionic 桩工厂；或探索 Shadow DOM 穿透方案 |
| **chunk 404** | 构建产物带 hash，旧缓存导致 chunk 404 | 入口内联 chunk；或设计器侧缓存失效策略 |
| **设计时/运行时双份** | 复杂组件需维护 design-components 与 canvas-stubs | 脚本从源码生成桩，减少手写 |
| **bundle 校验** | 主工程 bundle 结构错误时难以定位 | 设计器加载时校验并打 warning；主工程构建后自检脚本 |
