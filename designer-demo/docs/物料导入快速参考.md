# 物料导入快速参考

> 本文档整理设计器如何从主工程导入物料资产包，供后续改造与维护时快速查阅。  
> 适用于：理解当前架构、排查问题、规划物料导入改造（降低维护成本、提升可扩展性）。

---

## 一、整体架构

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 主工程（如 mobilebanking）                                                │
│   lowcode-materials/                                                    │
│   ├── manifest.json         物料清单                                    │
│   ├── entries/              组件入口（mr-components.js, mp-xxx.js）     │
│   ├── design-components/    设计时兼容版（mp-input-designer.vue 等）    │
│   ├── canvas-stubs/         store/router/i18n 桩 + Ionic 桩            │
│   └── scripts/              提取 token、样式、生成 bundle               │
│                                                                         │
│   pnpm run build:designer-materials                                      │
│         ↓                                                                │
│   dist/lowcode-materials/                                                │
│   ├── bundle.json           符合 TinyEngine 物料协议                     │
│   ├── mr-components.js      原子组件统一入口                            │
│   ├── mp-*.js               业务组件 ESM                                │
│   └── mr-bank.css           样式                                        │
└─────────────────────────────────────────────────────────────────────────┘
                                    │
                    npx serve dist/lowcode-materials -p 3000 --cors
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────┐
│ 设计器（designer-demo）                                                  │
│   engine.config.material: ["/mock/bundle.json", "http://localhost:3000/bundle.json"] │
│         ↓                                                                │

│         ↓                                                                │
│   画布 iframe：import(scriptUrl) 加载组件，import map 解析 @local/*       │
└─────────────────────────────────────────────────────────────────────────┘
```

## 二、物料资产包协议（核心字段）

### 2.1 顶层结构

```json
{
    "data": {
        "framework": "Vue",
        "materials": {
            "components": [], // 组件列表
            "snippets": [], // 物料面板分组与展示
            "blocks": [] // 区块列表（可选）
        }
    }
}
```

### 2.2 组件配置（components）

| 字段             | 类型   | 说明                                                     |
| ---------------- | ------ | -------------------------------------------------------- |
| `component`      | String | 画布渲染时的组件名，对应 Vue 组件名                      |
| `group`          | String | 分组（如「原子组件」「业务组件」）                       |
| `npm.package`    | String | 包名或占位符（如 `@local/mp-card`）                      |
| `npm.script`     | String | 脚本 URL，**必须是 ESM**，画布通过 `import(script)` 加载 |
| `npm.exportName` | String | 导出名（如 `MpCard`）                                    |
| `npm.css`        | String | 样式 URL（可选）                                         |
| `schema`         | Object | 属性 properties、事件 events、插槽 slots                 |
| `icon`           | String | 物料面板图标名                                           |

### 2.3 物料面板配置（snippets）

-   `group`：折叠面板标题
-   `children[].snippetName`：对应 `components` 中的 `component`
-   `children[].schema`：拖入画布时的默认 schema

### 2.4 必守规则（本工程约定）

-   **图标**：物料需配置 `icon` 或使用默认 `component-default`
-   **分组**：`group` 使用 `"原子组件"` / `"业务组件"`，英文由设计器自动翻译
-   **名称**：`name` 必须包含 `zh_CN` 与 `en_US`

## 三、原子组件（mr-_）与业务组件（mp-_）

### 3.1 原子组件

-   **来源**：Vant + Ionic（@mr/wise-core），主工程有样式覆盖
-   **统一入口**：`entries/mr-components.js`，按主工程 resolver 命名 re-export
-   **策略**：
    -   Vant 原子：直接 re-export
    -   Ionic 原子（如 MrImg）：可做设计态占位（无 src 时显示占位，有 src 渲染真实组件）
    -   Ionic 原子（Shadow DOM）：用画布桩 + 样式自注入（MrSegment、MrSegmentButton、MrLabel）

### 3.2 业务组件

-   **简单组件**：直接引用主工程源码（如 `mp-card.js` → `import MpCard from '../../src/components/mp-card.vue'`）
-   **复杂组件**：使用设计时兼容版或画布桩（画布桩可有效规避重依赖、保持物料轻量）
    -   `design-components/mp-input-designer.vue`：用 Vant `MrField` 做轻量封装（与主工程 `mp-input` 一致）；表单场景物料统一用 **MpInput**，不再单独拖 `MrField` 物料
    -   `canvas-stubs/components/mp-account-input-canvas.vue`：画布桩，保留结构替换复杂子组件
-   **组件内用 $t 的**：若画布显示 i18n key 而非译文，需做 canvas 桩并在桩内 `import { t as $t } from '../vue-i18n'`，在 canvas-stubs/vue-i18n.ts 的 FALLBACK 中补充 key（如 MpAgreementButton、MpAccountInput）
-   **重依赖组件**（vue-pdf-embed、pdf.js、复杂图表等）：做 canvas 桩占位，避免 chunk 膨胀与 worker 配置问题（如 MpPdf）

### 3.3 依赖关系

-   业务组件依赖原子组件，构建时 `@local/mr-components` 为 external，由设计器画布提供
-   画布需注入 Vant、Ionic 的脚本与样式，以及主工程提取的 design-tokens、base-overrides

## 四、设计器侧物料加载流程

1. **配置物料源**：`engine.config.material` 数组，支持多 bundle
2. **拉取**：`getMaterialsRes()` 请求各 URL，合并 `components`、`snippets`
3. **注册**：`addMaterials()` 写入 `materialState`
4. **画布依赖**：`getCanvasDeps()` 组装 scripts/styles，`updateCanvasDeps()` 通知画布更新 import map
5. **拖拽渲染**：画布通过 `npm.script` 的 URL 做 `import(script)` 动态加载组件

### 4.1 环境变量与注入

-   `VITE_MATERIAL_BUNDLE_URLS`：逗号分隔的多个 URL（非插件本地联调）
-   `window.TINY_MATERIAL_BUNDLE_URLS`：VSCode 插件注入

## 四点五、静态发布与版本化（推荐）

你们当前物料包产物中 `bundle.json` 的组件脚本/样式多为**相对路径**（例如 `mr-components.js`、`mp-*.js`、`mr-bank.css`），因此最推荐的发布方式是：将整个 `dist/lowcode-materials/` 作为**同目录静态资源**发布，并使用**带版本号的目录**避免缓存与回滚困难。

### 4.5.1 为什么要版本化目录

-   **缓存**：浏览器/CDN/代理可能缓存 `bundle.json` 与 chunk；若文件名不变，刷新也可能仍取到旧内容。
-   **回滚**：带版本目录可直接切回旧版本 URL，不需要覆盖文件或清缓存。
-   **诊断**：一眼能从 URL 看出“设计器正在使用哪个 buildId”。

### 4.5.2 推荐的发布目录结构

主工程执行 `pnpm run build:designer-assets` 后，会生成：

-   `dist/lowcode-materials/`：当前最新构建（供本地 serve）
-   `dist/lowcode-materials-releases/<buildId>/`：版本化发布目录（供静态发布/回滚）
-   `dist/lowcode-materials-releases/latest.json`：记录最新 buildId

静态发布建议把 `dist/lowcode-materials-releases/` 作为发布根之一，使 URL 形如：

-   `https://static.example.com/lowcode-materials/<buildId>/bundle.json`

> 说明：`<buildId>` 默认形如 `1.0.1-248-YYYYMMDDHHmmss`，也可通过环境变量 `LOWCODE_MATERIALS_BUILD_ID` 指定。

### 4.5.3 设计器如何使用“私服/静态地址”

设计器只需要 URL：

-   **插件注入**：`window.TINY_MATERIAL_BUNDLE_URLS = ['https://.../<buildId>/bundle.json']`
-   **非插件联调**：`VITE_MATERIAL_BUNDLE_URLS=https://.../<buildId>/bundle.json`

并确保静态服务满足：

-   **CORS**：允许设计器 iframe 跨域 GET（至少 `bundle.json`、CSS、ESM 脚本）
-   **MIME**：`.js` 为 `application/javascript`（ESM 可 import），`.css` 为 `text/css`，`.json` 为 `application/json`

### 4.5.4 当前阶段的决策（避免误解）

受限于当前**缺少静态发布工具/权限**，团队暂时按以下方式推进：

-   **短期（当前）**：继续使用本地 `serve` 进行联调与验证（最接近现有流程）
    -   `npx serve dist/lowcode-materials -p 3000 --cors`
    -   设计器配置：`VITE_MATERIAL_BUNDLE_URLS=http://localhost:3000/bundle.json` 或插件注入 `window.TINY_MATERIAL_BUNDLE_URLS`
-   **中期（待定）**：与 VSCode 插件开发者对齐 ASSETMANAGER 能力后，再决定最终落地为：
    -   **静态发布（推荐）**：CDN/文件服务器托管版本化目录（URL 直接可访问 `bundle.json`）
    -   **npm 私服分发**：发布为 npm 包，由插件安装后本地 serve，再注入 URL（registry 本身不直接暴露 `bundle.json` 文件目录）

> 因此：本文档虽给出“静态发布与版本化”的推荐形态，但**不代表当前必须立刻上私服发布**；现阶段目标是先把产物与导入链路跑稳，并与插件侧共同确定最终分发方案。

## 四点六、主工程脚本命令速查（mobilebanking）

> 目的：减少“命令太多导致迷惑”。这里按**最常用/按需/未来发布**分组，并说明它们之间的依赖关系与产物落点。

### 4.6.1 本地联调（必用）

-   **`pnpm run build:designer-materials`**
    -   **用途**：生成设计器可用的物料资产包（bundle + 组件 ESM + 样式），供本地 `serve` 或插件注入 URL。
    -   **产物**：`dist/lowcode-materials/`（含 `bundle.json`、`mr-components.js`、`mp-*.js`、`mr-bank.css`、`runtime.js` 等）
    -   **说明**：它内部已包含 token/资源/覆盖提取与 vite build（见脚本串联）。

### 4.6.2 样式产物（按需，推荐与物料联调一起跑）

-   **`pnpm run build:lowcode-styles`**
    -   **用途**：生成设计器可用的公共样式产物（`styles.json` + `tokens.css` + `utilities.css`）。
    -   **产物**：
        -   `dist/lowcode-styles/`（规范产物目录，便于检查）
        -   若存在 `dist/lowcode-materials/`，会**同步复制**到 `dist/lowcode-materials/`（这样本地只需 `serve dist/lowcode-materials` 一个目录）
    -   **说明**：缺类时修改 `lowcode-styles/safelist.extra.txt` 后重跑即可。

### 4.6.3 版本化发布目录（未来静态发布/回滚用，当前可保留但非必跑）

-   **`pnpm run versionize:lowcode-materials`**
    -   **用途**：把 `dist/lowcode-materials/` 复制到版本化目录，便于未来上传静态服务器/CDN，并支持回滚。
    -   **产物**：`dist/lowcode-materials-releases/<buildId>/` + `dist/lowcode-materials-releases/latest.json`
    -   **说明**：当前阶段若只做本地联调，可以不执行；等具备静态发布权限再纳入流水线。

### 4.6.4 一键全量（当前可用，但容易让人误以为“必须发布”）

-   **`pnpm run build:designer-assets`**
    -   **实际做的事**：`build:designer-materials` + `build:lowcode-styles` + `versionize:lowcode-materials`
    -   **何时用**：
        -   想同时更新物料与样式，并生成版本化目录（例如交付给别的同学/未来上静态发布）
    -   **当前阶段建议**：
        -   你们目前以本地 `serve` 测试为主，可先分别运行 `build:designer-materials` + `build:lowcode-styles`；`versionize` 暂不强制。

### 4.6.5 其它 extract 工具（一般不直接跑）

这些命令主要用于**排查/单步执行**，或被 `build:designer-materials`/`build:lowcode-styles` 间接调用：

-   `pnpm run extract:design-tokens`：从 `src/themes/styles/default-light.css` 提取画布 token（供物料/样式复用）
-   `pnpm run extract:canvas-assets`：提取画布需要的资源
-   `pnpm run extract:base-overrides`：提取基础覆盖样式
-   `pnpm run extract:canvas-styles`：按配置提取画布样式（特定场景）

## 五、主工程新增组件流程（当前）

### 5.1 新增原子组件（mr-\*）

1. 在 `entries/mr-components.js` 中增加 re-export（Vant/Ionic/桩）
2. 在 `manifest.json` 的 `components` 中增加一条
3. 若为 Ionic 桩，在 `canvas-stubs/components/` 下实现
4. **若组件内容在 slot 中**（如 MrLabel、MrButton）：schemaExtra 用 `property: "children"` + InputConfigurator（单行输入），并设置 snippetSchema 默认 children；否则运行时不显示（详见《Ionic 组件导入与桩方案》2.6 节）
5. **属性选项一律展示英文**：SelectConfigurator 等 options 的 label 用英文（如 Default、Primary、Large；`MrButton` 的 `nativeType` 用 `button`/`submit`/`reset` 即可），**勿加中文或括号说明**；**修改 manifest 后须在主工程执行 `pnpm run build:designer-materials`**，设计器使用新生成的 `bundle.json` 后属性面板才会与源码一致
6. **画布桩必须可见**：桩样式设 `min-height`，slot 提供默认内容（如 `Loading...`），确保拖入后画布始终有占位，便于定位
7. **事件不写进 snippet**：snippetSchema.props 只含属性默认，不含事件 handler，否则会覆盖用户绑定；事件在 schemaExtra.events 声明，由用户在「高级」→「事件绑定」中配置
8. **事件方法注释**：若事件 handler 需调用特定 API（如 `evt.target.complete()`），可在 BindEventsDialog 的 rewriteMethodParams 中，按 eventName 注入带注释的默认方法体

### 5.2 新增业务组件（mp-\*）

1. 在 `entries/` 下新增 `mp-xxx.js` 入口
2. 在 `manifest.json` 中增加物料配置
3. 若需设计时版：在 `design-components/` 或 `canvas-stubs/components/` 下实现
4. 若需样式提取：在 `extract-canvas-styles.cjs` 的 `STYLE_CONFIG` 中配置

### 5.3 导入顺序

先保证 mr-_ 可用，再接入依赖它们的 mp-_。

## 六、当前痛点与可改造方向（待后续尝试）

| 痛点                  | 现状                                                     | 可改造方向                                                |
| --------------------- | -------------------------------------------------------- | --------------------------------------------------------- |
| **manifest 冗长**     | 每个组件一条完整 JSON，schemaExtra 重复、难维护          | 按组件拆分 JSON + 脚本合并；或 schema 从组件源码/类型推导 |
| **多入口分散**        | 每个组件一个 entry 文件，新增需改多处                    | 单入口 + 动态注册；或脚本根据 manifest 自动生成 entries   |
| **样式提取繁琐**      | 多个 extract 脚本，需手动配置 STYLE_CONFIG、ASSET_CONFIG | 统一提取流水线；或约定目录结构自动发现                    |
| **Ionic 桩维护**      | 每个 Ionic 组件需单独桩 + 样式自注入                     | 通用 Ionic 桩工厂；或探索 Shadow DOM 穿透方案             |
| **chunk 404**         | 构建产物带 hash，旧缓存导致 chunk 404                    | 入口内联 chunk；或设计器侧缓存失效策略                    |
| **设计时/运行时双份** | 复杂组件需维护 design-components 与 canvas-stubs         | 脚本从源码生成桩，减少手写                                |
| **bundle 校验**       | 主工程 bundle 结构错误时难以定位                         | 设计器加载时校验并打 warning；主工程构建后自检脚本        |
