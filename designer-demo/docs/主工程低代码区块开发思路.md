# 主工程低代码区块（Block）开发思路

> **适用范围**：OAB 主工程 + VSCode 低代码插件 + `lowcode-kit` 出码链路。  
> **读者**：需要在主工程中设计、出码、嵌入「低代码区块」的开发者与 AI Agent。  
> **文档状态**：2026-08-27，基于 **Block POC 已跑通** 后的固化结论与后续规划。  
> **相关文档**：[主工程低代码集成指南-OAB](./主工程低代码集成指南-OAB.md)、[主工程低代码资源操作手册](./主工程低代码资源操作手册.md)、[组件导入注意事项](./组件导入注意事项.md)

## 0. 先读这一节

### 0.1 这里的「区块」指什么

| 概念 | 含义 | 是否本文目标 |
|------|------|-------------|
| **低代码 Block（本文）** | 可独立出码、嵌入主工程任意页面的 **复杂组件片段**（可含多子组件、state、methods、i18n） | ✅ |
| **TinyEngine 原 Block** | BlockManage 面板、物料 Block 页签等官方区块体系 | ❌ 已隐藏，不用 |
| **MpBlock / mp-block** | 主工程业务 **容器组件**（padding/背景分区） | 可选物料，与低代码 Block **不冲突** |
| **MpPage / mp-page** | 主工程 **整页壳**（header/content/footer） | 页面用；区块 **不要**再包一层 |

**一句话**：低代码 Block = 「出码后的 Vue 组件」，给非低代码页面或低代码宿主页 **局部 import** 使用。

### 0.2 Page vs Block（出码层已分离）

| 维度 | Page（页面） | Block（区块） |
|------|-------------|---------------|
| schema 标志 | `isPage: true` | `isPage: false` |
| schema 目录 | `src/lowcode/modules/{module}/` | `src/lowcode/block/{folder}/` |
| 出码产物 | `modules/.../views/*.vue` + `routes/*.ts` | `block/.../views/*.vue`（**无 route**） |
| 根节点后处理 | 出码可补 `<mp-page>` | **跳过** mp-page 后处理 |
| 插件 Run 预览 | ✅ 走路由 `#/lowcode/lowcode-{route}` | ❌ **不支持**（需宿主页预览） |
| 设计器根 schema | `componentName: "Page"` | 同为 `Page`（尚未与 Page 根彻底拆分，**不阻塞开发**） |

## 1. 固化结论（POC 已验证，2026-08-27）

以下结论来自 `block-preview` + `block-demo` 宿主页 POC，**可作为团队默认约定**。

### 1.1 已跑通链路

```
插件 BLOCK 树 Create Block
    → 设计器编辑（block 模式）
    → Save 出码 → src/lowcode/block/{name}/views/*.vue
    → 宿主页 / 业务页手写 import 区块组件
    → 运行预览（通过宿主 Page 的 Run 或 dev 路由）
```

### 1.2 POC 验收项（block-preview）

| 项 | 验证方式 | 结果 |
|----|----------|------|
| **出码** | `block-preview.json` → `block/main/views/block-preview.vue` | ✅ |
| **嵌入** | `block-demo.vue` 中 `import BlockPreview from '@/lowcode/block/...'` | ✅ |
| **state** | 区块内 `pocClickCount` 随按钮递增 | ✅ |
| **i18n** | 区块内 `t('main.quickLinks')` 显示正常 | ✅ |
| **methods** | `onBlockPocClick`，Console `[block-preview POC]` | ✅ |
| **lowcodeWrap** | 区块 SFC 与 Page 相同 inject / wrap 模式 | ✅ |

### 1.3 设计约定

1. **Block 根节点**：按需使用 `div` / `MpContainer` / `MpBlock`；**禁止**在区块最外包 `MpPage`。
2. **Page 根节点**：低代码页可自选是否拖 `MpPage`；与 Block 无关。
3. **预览方式**：Block **没有**插件 Run；必须嵌入 **宿主页**（低代码 Page 或业务 Vue 页）后预览。
4. **嵌入方式（POC 阶段）**：宿主页 **手写 import** 出码 `.vue`，模板中使用 `<BlockXxx />`。
5. **宿主页职责**：只当容器，**不在宿主页上重复验证** Block 的 state/i18n（避免与区块逻辑混淆）。
6. **物料修改**：改 `lowcode-materials/` 后必须 `pnpm run build:designer-materials`，再 Reload Extension Host + ASSETMANAGER Refresh；仅 Reload 窗口 **不会**更新画布物料。

### 1.4 当前样例文件（OAB）

| 角色 | 路径 |
|------|------|
| Block schema | `src/lowcode/block/main/block-preview.json` |
| Block 出码 | `src/lowcode/block/main/views/block-preview.vue` |
| 宿主页 schema | `src/lowcode/modules/demo/block-demo.json` |
| 宿主页出码 | `src/lowcode/modules/demo/views/block-demo.vue` |
| 预览路由 | `#/lowcode/lowcode-block-demo` |

### 1.5 已知限制 / 非阻塞项

- **Block Run**：插件明确不支持；后续可做专用预览宿主页，非必须。
- **inputs / outputs**：schema 预留父子通参，POC 未验；父页需传参时再补。
- **LowcodeBlock 注册表**：避免多处手写 import 的抽象，**第二阶段**再做。
- **宿主页出码覆盖**：`block-demo.vue` 中手动 `import BlockPreview` 在再次 Save 宿主页 schema 时可能被覆盖，需重新加 import 或改用专用 `block-host` 页。
- **Console 警告**：宿主页 demo 组件（如 `MpImage` 缺 `src`）与 Block POC 无关，可单独清理。

## 2. 如何开发一个 Block

### 2.1 创建

1. VSCode 插件侧边栏展开 **BLOCK** 分区（点击 BLOCK 标题使工具栏聚焦）。
2. 点击 **Create Block**（文件+号图标）。
3. 填写名称，生成 `src/lowcode/block/{folder}/{name}.json`，且 **`isPage: false`**。

> BLOCK 与 PAGE 的创建按钮 **分属不同树视图**；在 PAGE 树上只能 Create Page。

### 2.2 设计

1. 在 BLOCK 树中打开 schema → **Open Designer**（block 模式）。
2. 从 **Materials / Component** 拖组件搭建 UI（TinyEngine 原 Block 面板已隐藏）。
3. 按需配置 **state**、**methods**、属性面板绑定（与 Page 相同 DSL）。
4. **Save** → 触发 `pageUpdate` 出码到同目录 `views/{fileName}.vue`。

### 2.3 出码产物

典型结构：

```
src/lowcode/block/main/
├── block-preview.json      # schema（isPage: false）
└── views/
    └── block-preview.vue   # 出码组件（标准 SFC + lowcodeWrap）
```

出码特征：

- **无** `routes/*.ts`
- **不** 强制包裹 `<mp-page>`
- script 中含 `lowcodeWrap`、`I18nInjectionKey.lowcode()`，与 Page 一致

### 2.4 画布物料注意

- 业务组件需 **designer 桩**（`*-designer.vue` + entry 指向桩），不可直接引运行态组件，否则画布「区块 Xxx 加载错误」。
- 案例：`MpDateInput` 已补 `mp-date-input-designer.vue`；改物料后见 §1.3 第 6 条 rebuild 流程。

## 3. 如何使用（嵌入主工程）

### 3.1 方案 A：低代码 Page 作宿主（POC 推荐，已采用）

**适用**：调试 Block、不污染业务页。

1. 新建或复用低代码 **Page**（如 `block-demo`）。
2. 页面内保留 `MpPage` + 必要布局。
3. 在出码后的宿主页 vue 中 **手动添加**（出码器暂不会自动 import Block）：

```vue
<script setup>
import BlockPreview from '@/lowcode/block/main/views/block-preview.vue';
</script>

<template>
  <mp-page ...>
    <BlockPreview class="mb-16px" />
    <!-- 其他宿主内容可选 -->
  </mp-page>
</template>
```

4. 对 **宿主页** 点插件 **Run**，或访问 `#/lowcode/lowcode-block-demo`。

```
┌─────────────────────────────────┐
│  block-demo（宿主 Page）         │
│  ┌───────────────────────────┐  │
│  │ BlockPreview（低代码区块） │  │  ← 验证对象
│  └───────────────────────────┘  │
│  tags / date-input ...（可选）   │  ← 宿主自己的组件
└─────────────────────────────────┘
```

### 3.2 方案 B：业务页嵌入（上线路径）

**适用**：真实场景，如首页 `tab-home.vue` 替换 `<home-grid />`。

```vue
<script setup>
import HomeGridBlock from '@/lowcode/block/home-grid/views/home-grid.vue';
</script>

<template>
  ...
  <HomeGridBlock v-if="!isNonAccount" class="mt-20px" />
  ...
</template>
```

前提：主工程 `main.ts` 已 provide `I18nInjectionKey` + `lowcode()`（OAB 已有）。

### 3.3 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| A 低代码宿主页 | 不改业务代码、可 Run 预览 | 需手写 import；Save 宿主页可能覆盖 import |
| B 业务页 | 最接近上线 | 区块不稳定时影响真实页面 |

**建议路径**：A 调试 Block → B 嵌入真实页面。

## 4. state / i18n / methods 在区块中的用法

与 Page **相同**，在 **Block schema** 的 `page_content` 里定义，出码后在区块 `.vue` 内运行。

### 4.1 state

```json
"state": {
  "pocClickCount": 0,
  "pocButtonLabel": "Click block POC"
}
```

模板绑定示例：`{{ state.pocClickCount }}` 或 JSExpression `'Block POC clicks: ' + this.state.pocClickCount`。

### 4.2 i18n

- 模板 / JSExpression：`t('main.quickLinks')` 或 `$t('common.xxx')`
- methods 内：`this.state.xxx = t('main.editQuickLinks')`（与 donations 等 Page 一致，依赖 script setup 闭包中的 `t`）
- 优先使用 **主工程已有 key**（如 `main.*`、`common.*`）；区块专用 key 可走 `lowcode.*`（需 i18n 出码 / 配置）

### 4.3 methods

```json
"methods": {
  "onBlockPocClick": {
    "type": "JSFunction",
    "value": "function onBlockPocClick(event) {\n  this.state.pocClickCount += 1\n  console.log('[block-preview POC]', this.state.pocClickCount)\n}\n"
  }
}
```

组件绑定：`"onClick": { "type": "JSExpression", "value": "this.onBlockPocClick" }`

### 4.4 区块 vs 宿主页：不要混验

| 逻辑写在哪 | 验证什么 |
|------------|----------|
| **Block schema** | 区块作为独立组件的能力 |
| **宿主 Page schema** | 页面路由、整页布局（Block POC 阶段可不再扩展） |

| 项 | 说明 | 优先级 |
|----|------|--------|
| **LowcodeBlock 注册表** | `<LowcodeBlock name="home-grid" />` 或配置表映射，避免手写 import | 中 |

## 7. 问题 → 改哪里

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 画布「区块 MpXxx 加载错误」 | 物料 entry 指向运行态组件 | 补 `*-designer.vue` + 改 entry + `build:designer-materials` |
| Reload 后物料仍旧 | 未 rebuild dist | `pnpm run build:designer-materials` + serve 3000 + AM Refresh |
| Block 点 Run 无反应 | 设计如此 | 用宿主页 Run |
| 宿主页看不到 Block | 未 import 出码 vue | 手写 import + 模板使用组件 |
| Save 宿主页后 import 丢失 | 出码覆盖 | 专用 block-host / 少 Save 宿主 schema |
| 区块 state 不更新 | 逻辑写在宿主 Page 上 | 改到 **Block schema** |
| 区块 i18n 不显示 | key 不存在 | 用已有 `main.*` / `common.*` 或补 lowcode i18n |
