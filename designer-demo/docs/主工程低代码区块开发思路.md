# 主工程低代码区块（Block）开发思路

> **适用范围**：OAB 主工程 + VSCode 低代码插件 + `lowcode-kit` 出码链路。  
> **读者**：需要设计、出码、嵌入「低代码区块」的开发者与 AI Agent。  
> **文档状态**：2026-08-31，基于 **Block POC + MpLowcodeBlock + 能力包装物料（MpQuickLinksRow）** 已跑通后的指导说明。  
> **相关文档**：[主工程低代码集成指南-OAB](./主工程低代码集成指南-OAB.md)、[主工程低代码资源操作手册](./主工程低代码资源操作手册.md)、[组件导入注意事项](./组件导入注意事项.md)、[主工程 composable 导入思路](./主工程composable导入思路.md)

## 0. 先读这一节（怎么用 Block）

### 0.1 日常三步（最常用）

```
① BLOCK 树 Create Block → 设计 → Save 出码
② 宿主 Page（如 block-demo）拖 MpLowcodeBlock，填 name = 出码 vue 文件名
③ 宿主页 Save / Run，或打开 #/lowcode/lowcode-block-demo
```

**换区块 / 加第二个区块**：改属性面板 **Block Name**，或再拖一个 `MpLowcodeBlock` 填另一个 `name`。  
**不用改** `block-registry.ts`（glob 自动发现）。

### 0.2 名词对照

| 概念 | 含义 | 是否本文目标 |
|------|------|-------------|
| **低代码 Block** | 可独立出码、嵌入页面的复杂组件片段（可含 state / methods / i18n） | ✅ |
| **`MpLowcodeBlock`** | MP 物料：按 `name` 挂载上述 Block 出码 SFC | ✅ 推荐嵌入方式 |
| **TinyEngine 原 Block** | 官方 BlockManage / 物料 Block 页签 | ❌ 已隐藏 |
| **MpBlock / mp-block** | 业务容器（padding/背景），可选拖入 | 与低代码 Block 不冲突 |
| **MpPage / mp-page** | 整页壳 | 页面用；区块根上 **不要**再包 |

### 0.3 Page vs Block

| 维度 | Page | Block |
|------|------|-------|
| `isPage` | `true` | `false` |
| 目录 | `src/lowcode/modules/...` | `src/lowcode/block/...` |
| 出码 | `views/*.vue` + `routes/*.ts` | `views/*.vue`（**无 route**） |
| mp-page 后处理 | 可强制包 | **跳过** |
| 插件 Run | ✅ | ❌（靠宿主页预览） |

| 挂载运行态 | `src/components/lowcode/mp-lowcode-block.vue` |
| 自动发现 | `src/lowcode/common/block-registry.ts` |
| Quick Links 横滑运行态 | `src/components/lowcode/mp-quick-links-row.vue`（内部用 `mp-quick-link-item`） |
| 画布桩 / 物料 | `lowcode-materials/design-components/mp-*-designer.vue`、`entries/mp-*.js`、`manifest.json` |
| 预览 | `#/lowcode/lowcode-block-demo`；Home 登录态看 Tab Home |

### 1.4 团队约定

1. 区块根可用 `div` / `MpContainer` / `MpBlock`，**禁止**最外包 `MpPage`。  
2. 嵌入优先用 **`MpLowcodeBlock`**（写进 schema），不要在低代码出码 vue 里手写 `import`。  
3. `name` = `views` 下文件名（不含 `.vue`）。  
4. 调试宿主用现有 **`block-demo`**；不做专用 `block-host`、不强制精简 demo。  
5. 改 `lowcode-materials/` 后必须 `pnpm run build:designer-materials` + Reload Extension Host + AM Refresh。  
6. **低代码专用运行态组件**统一放 `src/components/lowcode/`（与 `base/` 等通用组件区分）；勿在 `base/` 做路径转发 shim。  
7. 主工程已有、但设计器**拖不动**的能力（如 Swiper）：做成包装物料，见 **§2.8**。

## 2. 以后怎么开发一个新 Block（操作手册）

### 2.1 创建

1. 侧边栏展开 **BLOCK**（点 BLOCK 标题，让工具栏出现 Create）。  
2. **Create Block** → 输入名称（如 `home-grid`）。  
3. 生成 `src/lowcode/block/.../{name}.json`，`isPage: false`，且 **`id` / `_id` 唯一**。

> 不要在 PAGE 树里找 Create Block；两个树的按钮是分开的。

### 2.2 设计与出码

1. 打开该 json → Open Designer。  
2. **在画布上**拖 MP/MR 组件搭 UI（不要手改 `views/*.vue` 的模板来“修样式”）。  
3. 复杂入口 / 横滑等优先做成 **可拖物料**（如 `MpQuickLinksRow`），再在 Block 里绑 list / loading / 事件。  
4. 需要时在 Block schema 写 **state / methods / i18n**。  
5. **Save** → 同目录生成 / 覆盖 `views/{name}.vue`。

> **反模式**：在出码 vue 里手写 `<component :is="item.icon">`、手改出码模板修样式。设计器再 Save 会冲掉，也偏离「用低代码开发区块」的目标。

出码结构示例：

```
src/lowcode/block/main/
├── home-grid.json
└── views/
    └── home-grid.vue    ← MpLowcodeBlock 的 name="home-grid"
```

### 2.3 挂到页面上（宿主）

1. 打开宿主 Page（推荐 `block-demo`）。  
2. 物料 **业务组件** → 拖 **Lowcode Block（MpLowcodeBlock）**。  
3. 属性 **Block Name** 填 `home-grid`（与文件名一致）。  
4. Save 宿主 → Run / 打开 `#/lowcode/lowcode-block-demo`。

同一页要多个区块：拖多个 `MpLowcodeBlock`，分别填不同 `name`。

### 2.4 换一个已挂载的区块

只改属性面板 **Block Name**（例如 `block-preview` → `block-preview2`），Save 后预览即可。  
**不必**改 `block-registry.ts`。

### 2.5 `block-registry.ts` 是干什么的？

运行时「按名字找 vue」的解析器，内部是：

```ts
import.meta.glob('@/lowcode/block/**/views/**/*.vue')
```

| 会做 | 你不用做 |
|------|----------|
| 自动扫描 `block/**/views/*.vue` | 每加一个 Block 往 map 里加一行 |
| `name` → 对应 loader | 手写 import 路径 |

> 注释里不要写裸的 `**/views/*.vue` 模式，部分 Vite 转换会误生成 `views;` 导致白屏（已踩坑）。

### 2.6 业务页嵌入（上线）

业务页不会被低代码出码覆盖，推荐与宿主同一套：

```vue
<mp-lowcode-block name="home-grid" class="mt-20px" />
```

也可直接 `import` 出码 SFC。前提：主工程已 provide `I18nInjectionKey` + `lowcode()`（OAB 已有）。

### 2.7 业务 Block 样例：Quick Links（含横滑）

已落地业务向 Block，并在 Home 真实替换原 `home-grid`；横滑通过包装物料 `MpQuickLinksRow` 完成（见 §2.8）。

#### 能力对齐（相对 `home-grid.vue`）

| 已对齐 | 说明 |
|--------|------|
| 标题 `main.quickLinks` + Edit 跳转 | schema 内 Text + methods |
| favorite / tenantServices 数据源 | `this.composables.homeQuickLinks` |
| 圆角方块 + 服务图标（无图标 Avatar） | Row 内部运行态 `mp-quick-link-item` |
| Swiper 横滑（`slidesPerView: 5`，`limit: 10`） | `MpQuickLinksRow` |
| 点击进服务路由 / loading 骨架 | Row 转发 click；内置 skeleton |

#### 关键文件

| 文件 | 作用 |
|------|------|
| `src/lowcode/block/main/home-quick-links.json` | **设计器编辑源**（改 UI 只改这里） |
| `src/lowcode/block/main/views/home-quick-links.vue` | Save 出码产物（勿手改模板修样式） |
| `src/components/lowcode/mp-quick-links-row.vue` | 横滑行运行态（Swiper + 内部 item） |
| `src/components/lowcode/mp-quick-link-item.vue` | 单入口运行态（**不**单独挂设计器物料） |
| `lowcode-materials/.../mp-quick-links-row*` | 画布 stub + entry + manifest |
| `src/lowcode/common/home-quick-links.ts` + `useHomeQuickLinks` | 数据绑定 |
| `tab-home.vue` | `<mp-lowcode-block name="home-quick-links" />` |

#### 做法要点（以后做业务 Block 可复用）

1. **流程**：画布搭 UI → Save → 宿主 / Home 运行。**不要**手改出码 vue 来对齐原组件。  
2. **复杂可视块做成物料**：动态图标、Swiper 等画布表达不了的，封装成 `MpXxx`，Block 只拖物料 + 绑 props。  
3. **优先选「自给自足」区块**：自己读 store，少依赖父页 props。  
4. **复杂依赖放 composable**：`this.composables.homeQuickLinks`（见 [composable 导入思路](./主工程composable导入思路.md)）。  
5. **回滚**：`tab-home` 改回 `<home-grid />` 即可。

### 2.8 经验固化：把主工程能力包装成可拖物料

> **背景**：`MpQuickLinksRow` 是在主工程**已有** `swiper` 依赖、且业务里已有 Swiper 用法的前提下，按低代码需要做的一层包装。  
> **结论**：设计器拖不动的依赖 / 能力，不要指望塞进 Resource utils；应包装成低代码专用组件，画布拖 stub，出码走真实现。

#### 为什么要包装

| 事实 | 含义 |
|------|------|
| 设计器物料面板只能拖 **已登记的组件** | 裸 `swiper/vue`、图表库等 **不能**直接当可拖节点 |
| Resource Management 里的 npm / utils | 进的是 Page JS 的 `this.utils`，**不是**画布可拖组件 |
| 出码后跑在主工程 | 主工程里已有的依赖（如 Swiper）**运行态本来就能用** |

所以：瓶颈在「画布能不能拖」，不在「出码后能不能用」。

#### 推荐三层分工

| 层 | 路径约定 | 职责 |
|----|----------|------|
| **运行态** | `src/components/lowcode/mp-xxx.vue` | 用主工程已有依赖实现真实能力（如 `swiper/vue`） |
| **画布 stub** | `lowcode-materials/design-components/mp-xxx-designer.vue` | 静态 / 简化外观，**不**引重依赖；表达布局与可滑动预览即可 |
| **物料登记** | `entries/mp-xxx.js` + `manifest.json` | 设计器可拖；`pnpm run build:designer-materials` |
| **区块 schema** | `src/lowcode/block/.../*.json` | 只拖包装组件，绑 `state` / 事件 |

```
设计器拖不动的能力（Swiper / 地图 / 图表 / 复杂业务块）
    → src/components/lowcode/ 包装运行态
    → *-designer.vue 画布 stub
    → manifest 登记
    → Block schema 拖 MpXxx + 绑 props
    → Save 出码 → 主工程真依赖生效
```

#### 包装什么（业务能力，不是裸库）

- ✅ **做**：`MpQuickLinksRow` = 横滑 + 入口项 + loading（对齐 `home-grid` 的一块能力）  
- ❌ **不做**：把裸 Swiper 壳当通用物料往面板里塞；也不要把单入口 `MpQuickLinkItem` 再单独挂设计器（若只作为 Row 内部实现）

内部子组件（如 `mp-quick-link-item.vue`）可以**只留运行态**，不进物料面板。

#### 以后同类需求怎么套

1. 确认主工程**已有**该依赖或现成业务写法。  
2. 在 `src/components/lowcode/` 写运行态包装组件。  
3. 写画布 stub（高度自洽、能暗示交互即可，不必 1:1 真 Swiper）。  
4. 登记物料并 rebuild；Block 里拖包装组件，**勿**手改出码 vue。  
5. 迁移组件路径后若出现旧路径 404：重启 `pnpm dev` 清 Vite 模块图即可，**不要**在 `base/` 加转发 shim。

#### 反模式

| 反模式 | 为什么不行 |
|--------|------------|
| 往 Resource 加 swiper npm，指望画布可拖 | utils ≠ 物料 |
| 手改 `views/*.vue` 塞 `<swiper>` | Save 覆盖；偏离低代码流程 |
| 低代码组件放 `base/` 再 shim 转发 | 冗余；统一放 `lowcode/` |
| 画布 stub 引入真实 Swiper / store | 物料包变重、易挂画布 |

## 3. Block 内 state / i18n / methods

逻辑写在 **Block schema**，不要写在宿主 Page 上「假装验证区块」。

### state

```json
"state": {
  "pocClickCount": 0,
  "pocButtonLabel": "Click block POC"
}
```

### i18n

- 表达式：`t('main.quickLinks')`  
- 优先主工程已有 key（`main.*` / `common.*`）

### methods

```json
"methods": {
  "onBlockPocClick": {
    "type": "JSFunction",
    "value": "function onBlockPocClick(event) {\n  this.state.pocClickCount += 1\n}\n"
  }
}
```

绑定：`"onClick": { "type": "JSExpression", "value": "this.onBlockPocClick" }`

## 4. 画布 vs 运行态（预期差异）

| 场景 | 预期 |
|------|------|
| 宿主页画布上的 `MpLowcodeBlock` | **占位 stub**（显示 name），不真跑区块业务 |
| 宿主页 Run / `#/lowcode/...` | 加载真实 `views/{name}.vue` |
| Block 自己的设计器画布 | 可编辑该 Block 的真实结构 |
| Block 设计器顶部 `/ xxx` | 当前 Block 的 **route 预览条**，不是 MpLowcodeBlock 的 name |
| `MpQuickLinksRow` 画布 | stub 静态横滑 + peek；**≠** 真机 Swiper 手势 |
| `MpQuickLinksRow` 运行态 | 真 `swiper/vue`，出码后 Home 可滑 |

### 4.1 出码：Page vs Block（`dsl-vue`）

Save（VSCode）调用 `generate({ type: 'page' | 'block' })`。以下差异是**有意**的；改后处理时不要再对 block「整段跳过」。

| 环节 | Page | Block | 说明 |
|------|------|-------|------|
| 路由插件 | ✅ 生成 `routes/*.ts` | ❌ 不生成 | Block 无独立路由 |
| SFC 后处理：剥 `children` / 修 mr-* slot | ✅ | ✅（2026-09-01 起） | **曾**对 block 整段 `return`，导致 MrButton 警告只在区块出现 |
| SFC 后处理：根节点改写为 / 提升 `<mp-page>` | ✅ | ❌ 跳过 | Block 禁止最外包 MpPage |
| Vue 输出目录 | `views/` | `views/` | 与 schema 同级；page 在 `modules/...`，block 在 `block/...` |
| 插件包更新 | rebuild `dsl-vue` **且** Reload Extension Host | 同左 | `dsl-vue` 打进 `vscode/dist/extension.js`，只 build 不 Reload = 旧逻辑 |

**仍须留意的隐患（非 page/block 分叉，但同类）：**

1. 官方出码会把面板 `props.children` 写成属性；后处理已剥 `mr-button` / `mr-label` / `mr-toggle` / `mr-title`。若新增「文案在 slot」的原子，要同步扩剥名单。  
2. 历史页面（如 donations）若仍带 `:children=`，需 **再 Save 一次** 才会被新后处理清掉。  
3. 改出码后处理：`pnpm --filter @mr/pex-dsl-vue build` → 视情况 rebuild vscode / **必 Reload Extension Host** → 再 Save 验证。

## 5. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 新 Block 画布顶部仍显示旧路由（如 `/ block-preview`） | 创建时 `id/_id` 曾写死为 `1`，与旧块冲突 | 已改为 `Date.now()`；旧文件改唯一 `_id` 后重开设计器 |
| 宿主再出码 Block 消失 | 手写 import 被覆盖 | 用 **`MpLowcodeBlock` 写进 schema** |
| 运行 not found | `name` ≠ 文件名 / 未出码 | 核对 `views/{name}.vue` |
| `ReferenceError: views is not defined` | registry 注释含危险 glob 字面量 | 勿在注释写 `**/views/*.vue` |
| 画布「区块 MpXxx 加载错误」 | 物料指运行态 | 补 `*-designer.vue` + rebuild 物料 |
| Block 点 Run 无效 | 设计如此 | 用宿主页 Run |
| Console `children` on `<button>` | 出码带 `children="..."`；block 曾跳过后处理 | Rebuild dsl-vue + Reload 插件后再 Save；见 §4.1 |
| Quick Links 一直骨架 + `useI18n` Must be called at the top of setup | 在 `import().then` / 异步回调里**首次**调用了含 `useI18n` 的 Pinia store | 用 `this.composables.homeQuickLinks`（lowcodeWrap setup 内创建） |
| `watchHomeQuickLinks is not defined` | 设计器重新出码冲掉了手写 `import` | 业务逻辑走 **composables / utils**，methods 只写 `this.composables.xxx`，勿依赖额外 import |
| `404 .../components/base/mp-lowcode-block.vue` | 组件迁到 `lowcode/` 后 Vite 仍缓存旧路径 | **重启 `pnpm dev`**；勿加 base 转发 shim |
| 画布看不出「可滑动」 | stub 项数 = slidesPerView，一屏刚好塞满 | stub 多放几项 + overflow + peek（见 `mp-quick-links-row-designer`） |
