## 五、导入经验摘录（mr-header 与画布桩）

1. **协议与出码**：`mr-header` 是容器，不宜默认只塞 `Text`；默认结构应对齐主工程高频写法（`Toolbar` + 返回 + 标题）。避免用 `slot` 属性模拟 `slot="start"` 却被出码成 `#start` 的坑；稳定后再考虑多 snippet 模板。
2. **设计器画布 vs 真机**：Ionic 的 `ion-header` / Shadow DOM 在设计器 iframe 里易出现「能出码但画布丑」；与 `mr-segment` 同类问题，**用画布桩**在 `mr-components.js` 中映射桩组件，样式用 `injectStubStyles` 注入，不依赖画布外全局 CSS。
3. **画布桩细节**：返回按钮可用主工程 `src/assets/icons/arrowLeft.svg` 作为设计态图标；标题与返回在桩内均用**绝对定位**（返回左、标题水平垂直居中），**与子节点在 Toolbar 内的 DOM 顺序无关**，避免「先拖标题再拖返回」时叠在一起。
4. **手动组装 vs 默认片段**：推荐 **MrHeader 下先放 MrToolbar，再在其中放 MrBackButton + MrTitle（顺序任意）**。若主工程运行态把 `mr-*` 解析为 **真实 Ionic**，则 `ion-header` 内一般**必须有 `ion-toolbar`**，否则子节点可能不渲染；若把 `BackButton`/`Title` 直接挂在空的 `Header` 下，画布桩虽能兜底，运行/预览可能异常。物料里 `MrHeader` 的 `childWhitelist` 已限制为仅 `MrToolbar`。
5. **component-base-style**：设计器默认给拖入组件加 `class="component-base-style"`（margin）。与 **MrSegmentButton** 类似，`MrToolbar` / `MrBackButton` / `MrTitle` / `MrButtons` 已加入 `COMPONENTS_SKIP_BASE_STYLE`，不再自动加该类；历史 schema 在 `patchSchemaWithMaterialDefaults` 中会清理；画布桩 CSS 仍对误带类名做 `margin: 0` 兜底。
6. **测试范围**：当前仅确认 **整段 MrHeader 拖拽** 效果可接受；**MrToolbar、MrButtons、MrBackButton、MrTitle 未单独**从物料面板拖入逐项验证，后续补测时可更新 2.1 说明或「待测试」计数。
7. **MrFooter / MrToolbar 空态**：当 `MrFooter` 默认包含 `MrToolbar` 时，`MrToolbar` 桩需要正确识别“设计器占位提示文本”并过滤，保证空态视觉干净；同时占位层要能铺满选中框而非偏左。
8. **mr-searchbar 功能对齐**：补齐主工程常用配置与事件（`v-model` 对应 `onUpdate:value`，`@ion-input/@ion-change` 等），并把画布桩图标（`search.svg`）、圆角与尺寸对齐，避免设计态误导出码效果。
9. **mr-refresher 的 slot 语义冲突**：Ionic 的下拉刷新依赖 `slot="fixed"`；但出码链路里 `slot` 可能被当成 Vue v-slot 简写生成 `#fixed`，导致功能直接失效。处理原则：**只有出现“语义冲突导致功能坏掉”时才改出码工具**；因此通过 VSCode 扩展的出码后处理对少量 `mr-*` 标签做 slot 修复（`#xxx` → `slot="xxx"`、`ionSlot` → `slot`），并保持出码仍为 `mr-*`，避免把工程组件习惯强耦合进出码器。默认文案与画布样式等“体验项”应放在物料 `manifest/snippetSchema` 与画布桩中实现，而非出码器。
10. **mr-progress-bar 设计态一致性**：进度条属于“视觉反馈型组件”，画布若使用示意色会造成配置误判。经验是：画布桩优先复用运行态同源变量（如 Ionic 的 `--progress-background` / `--background`），并在尺寸上对齐真实组件（细条高度），确保“画布所见≈出码所得”。
11. **mr-switch 的 v-model 语义**：开关类组件若出码为 `modelValue="true"` 这类常量，将无法把值写回父组件，运行态表现为“点击无效/回弹”。处理原则：对需要双向绑定语义的 props（如 `modelValue`），在拖拽生成节点与保存/预览前补丁中，自动改写为 `JSExpression + model:true` 绑定 `this.state.xxx`，并自动创建对应 state 变量；同时将该组件加入 `COMPONENTS_SKIP_BASE_STYLE`，避免被 `component-base-style` 的 `width:100%` 拉满造成布局误导。
12. **mr-collapse 的 v-model 语义（容器类同理）**：折叠面板的展开态同样依赖 v-model 写回（数组/字符串）。若出码把 `modelValue` 固化为常量，运行态点击标题不会持久展开。处理原则同上：拖拽时自动创建 `this.state.mrCollapseN` 并用 `JSExpression + model:true` 绑定，保存/预览前兜底修正，保证交互组件“出码即能用”。并建议在物料 `nestingRule` 限制子节点为 `MrCollapseItem`，降低误用成本。
13. **mr-collapse-item 也要跳过 component-base-style**：折叠项是 Collapse 的布局子项，若自动附加 `component-base-style`，可能引入 `margin/width:100%` 等基础样式，导致画布与出码布局被误导。处理原则：将 `MrCollapseItem`（以及 `MrCollapse`）加入 `COMPONENTS_SKIP_BASE_STYLE`，并在保存/预览前补丁中清理历史误带。
