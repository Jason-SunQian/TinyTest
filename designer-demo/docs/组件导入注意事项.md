# 组件导入注意事项

本文档约定**组件导入与设计时兼容的规则**，后续执行（新增原子/业务组件、排查画布不显示等）均应在这些规则下进行；并收录**经验总结**，避免重复踩雷、便于他人查阅。

---

## 一、组件导入规则（必须遵守）

### 1.1 原子组件（MR 开头）

-   **默认一律使用第三方库源码**（Vant / Ionic），不手写“另一个实现”来替代原子组件。
-   主工程用哪个库的原子（Vant 还是 Ionic），设计器就提供哪个：该用 Vant 用 Vant、该用 Ionic 用 Ionic，与主工程 resolver 命名一致。
-   在主工程中被**高频使用**的原子（如 mr-img），应作为**物料**在面板中展示并可拖拽，且使用**真实实现**（主工程用 Ionic 的 ion-img 就导出 Ionic 的 MrImg），不得用「原生 `<img>` + 手写 CSS」等桩替代。
-
-   **允许的最小“设计态包装”例外（推荐做法）**：当第三方原子组件在缺少关键 prop（如 `src`）时会出现**0 尺寸/不可见**，导致画布“拖进来啥也看不到、选不中”时，可以在物料入口对该原子做一个**轻量包装**：
    -   `src` 等关键 prop **有值**：仍渲染**真实第三方组件**（保持与主工程一致）
    -   关键 prop **无值**：渲染一个**可见占位 DOM**（设置 `minWidth/minHeight`、边框/背景/提示文本），确保可选中/可配置
    -   该包装必须是**同名导出**（如仍导出 `MrImg`），且逻辑尽量简单，避免引入大量自定义样式与复杂行为

### 1.2 设计器环境与依赖

-   设计器与主工程一致地**同时引入 Vant 和 Ionic**；设计器依赖中必须包含 Ionic（与主工程同版本或兼容版本），画布 iframe 内注入两者的脚本与样式。
-   画布内「该用哪个就用哪个」：组件从 mr 统一入口按主工程 resolver 导出，设计器只负责提供完整运行时与样式。

### 1.3 业务组件（MP 开头）

-   **优先使用主工程源码**；能通过「设计器引入 Vant + Ionic + 提取主工程样式」正常显示的，不造桩。
-   **仅**在以下情况才为业务组件做设计时桩（原生标签 + 手写 CSS）：
    -   该组件**极其复杂**，或
    -   在画布上**即使用完整依赖也无法正常表现**。
-   做桩时需考虑**降低维护成本**：尽量使用通用脚本/模板，避免每个组件从零手写大量 CSS。

### 1.4 样式与物料配置

-   主工程对 **Vant** 的样式覆盖应通过**提取全局样式**在设计器中使用，保证画布与主工程视觉一致。
-   **Ionic 组件**：提取样式对画布无效（Shadow DOM 导致外部 CSS 无法穿透），需采用**桩 + 样式自注入**，详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md)。
-   **Ionic 桩的 v-model 协议**：若组件有 value 绑定（如 MrSegment），manifest 的 events 需配置 `onUpdate:value`；子组件（如 MrSegmentButton）的 value 必须唯一，出码前由 `patchSchemaWithMaterialDefaults` 做唯一性修正。
-   **ion-segment 内按钮对齐**：历史上画布会给新拖拽组件自动附加 `component-base-style (margin)`，会破坏 MrSegmentButton 这类 flex 子项对齐；当前设计器已改为**全局不注入且在拖拽/出码前统一剥离 `component-base-style`**，因此无需再维护“跳过列表”，对齐问题应从组件桩自身样式与结构层面解决。
-   每个需要在面板拖拽的原子组件，在 bundle 的 `components` 中必须有对应物料条（`component`、`npm.script`、`npm.exportName` 等），与 MrDivider 的配置方式一致。
-   **视觉反馈类组件（强规则）**：如 `mr-progress-bar`、`mr-switch`、`mr-checkbox` 等，画布桩必须优先复用运行态同源主题变量（如 Ionic CSS 变量），禁止长期使用“示意色/临时色”替代真实视觉；否则会误导配置判断，导致“画布看起来对、出码效果不对”。
-   **视觉反馈类组件验收标准（必须同时满足）**：① 颜色/主题跟随运行态变量；② 关键尺寸（高度、圆角、描边粗细）与运行态同量级；③ 关键状态（默认/激活/禁用/加载）在画布中可识别且与出码语义一致。
-   **画布桩与相邻 `MrField` 横向基准（强规则）**：凡画布桩用「裸根节点 + 自绘背景/下划线」模拟业务 `mp-*`（未用 `MrField`/`van-cell` 包裹）的，**根容器必须**与主工程表单一致地吃掉横向 inset：`padding-left/right` 使用 `var(--van-cell-horizontal-padding, var(--mp-horizontal-padding, 16px))`（与主工程 `canvas-stubs` 里 `base-overrides` / `MrField` 画布桩同一套 token）。**禁止**在根级与「灰底/内容区」子层**重复叠同一套横向 padding**（否则要么灰框相对 Title 左凸，要么框内文字离灰边多出一截），导致「画布对齐、预览不对齐」或反复单组件微调。**新增/改画布桩时按本条自检**，避免每个物料各写一套 magic number。
-   **高频循环组件（推荐规则）**：若某组件在主工程高频以循环渲染使用（如 `mr-collapse-item`），允许在拖拽阶段注入“可回退的循环模板”（`loop/loopArgs/key` + 示例 state 列表），确保用户拖拽后立即看到循环效果。模板必须可一键改回普通节点（清空 loop）且不影响手工配置。
-   **组合交互组件（强规则）**：若组件必须与子组件配合才有功能（如 `mr-item-sliding` 需 `mr-item-options`/`mr-item-option`），`snippetSchema` 必须提供“拖拽即用”的完整最小示例，并在 `nestingRule` 中限制父子结构，避免用户拖入后看不到交互或结构搭错。
-   **多 item 结构组件（强规则）**：`mr-reorder-group`、`mr-cell-group` 这类真实场景常包含多条 item 的组件，`snippetSchema` 不可只给空壳或单项，必须默认提供 2~3 条示例并体现差异化配置（如 `isLink`），确保拖拽后立即看懂结构与配置入口。
-   **Reorder 交互闭环（强规则）**：`mr-reorder-group` 的事件处理必须调用 `event.detail.complete()`；若仅绑定事件而未完成回调，运行态会出现拖拽后卡住，误导为组件不可用。
-   **列表类桩视觉一致性（强规则）**：`mr-item`/`mr-item-sliding` 等列表组件的画布桩背景、边框、圆角必须对齐运行态；背景优先走 Ionic 变量链（`--background -> --ion-item-background -> --ion-background-color`），禁止额外装饰（如运行态不存在的圆角/外框）造成误导。
-   **Group 选择类组件 v-model（强规则）**：`mr-radio-group`、`mr-checkbox-group`、`mr-collapse`、`mr-switch` 等依赖双向绑定的组件，禁止以常量 `modelValue` 作为默认可运行示例；必须在拖拽落盘与保存/预览补丁阶段自动改写为 `JSExpression + model:true` 绑定 `this.state.xxx`，并自动创建对应 state（单选默认首项、多选默认数组），保证“拖拽即能点击交互”。
-   **表单字段 v-model（强规则）**：`mr-form` 下应使用 **`MpInput`（mp-input）** 作为输入项（不再推荐使用物料 `MrField`）；必须把 **`modelValue` 绑定到页面根 `state` 的嵌套字段**（如 `this.state.mrForm1.email`），否则设计态输入会在重渲染后丢失、校验仍像未填；拖拽 `MrForm` 时应自动创建 `state.mrFormN` 对象并为各 `MpInput` 写入绑定。`patchSchemaWithMaterialDefaults` 递归时必须共享**根 schema 的 `state` 引用**，避免在子节点上把补丁写到空 `state`。面板需暴露 `MpInput` 的 `modelValue` 以及 `name` / `rules`（与 `mr-form` 校验一致）。历史 schema 中若仍含 `MrField`，保存前补丁会一并处理。
-   **MpInput 的 `complete` 与主工程一致**：主工程常在 `mr-form` 里对每个 `mp-input` 绑定 `@complete`，在回调里根据 **多处字段** 或接口结果汇总校验，再 **`emit('validate', true/false)`** 或写 **`state`** 控制「下一步/提交」按钮。设计器物料已为 `MpInput` 注册 **`onComplete`**（出码为 `@complete`）；设计器桩在 **失焦** 时也会触发 `complete`，便于演示。默认 `MrForm` 片段会绑定 **`this.onDemoFormRecalculateSubmit`**（根据 `this.state[this.state.demoFormTargetKey]` 聚合校验并设置 **`formDemoSubmitEnabled`**）及 **`onSubmit` → `this.onDemoFormSubmit`**（把 Vant 提交的 **`values` 写入 `formDemoLastSubmit`**）；拖拽 `MrForm` 时若页面尚无这两个方法会自动写入 **`methods`**。多表单场景请自行区分 `demoFormTargetKey` 或改为独立方法。
-   **slot 文本回显一致性（强规则）**：`MrLabel`、`MrButton`、`MrToggle` 这类“文本存于 `children`”的组件，必须在属性面板读取前执行 `children <-> props.children` 同步；若二者冲突，一律以 `schema.children` 为真值源回写 `props.children`，避免“画布/出码生效但二次选中回显旧值”。
-   **属性面板改动必须在画布可见（强规则）**：当某 MP 组件使用 `design-components/*-designer.vue`（画布桩）时，**画布桩不得把展示写死**。凡是在 `manifest.schemaExtra.properties` 暴露给属性面板的 props，画布桩至少要满足“改了能看见变化”（哪怕只是占位文案/条数/禁用态），否则会出现“属性面板看起来能改、画布毫无反馈”的误导。
    -   **典型反例**：画布桩固定渲染 2 条演示项、完全不读取 `props`，导致用户误以为“属性不生效/物料没接上”。
    -   **推荐做法**：选择 1~2 个对画布最有反馈、且不会改变运行态业务语义的 prop 做演示映射（例如 `text` 改前缀文案、`skeletonNum` 改演示行数上限），其余保持运行态语义并在属性描述里说明“仅影响运行态/仅在无数据时生效”等限制。
-   **最小验收清单（强规则，导入后必须过一遍）**：
    -   **画布**：拖入后，修改 1~2 个基础 props，画布立即有可见变化（不依赖刷新页面/重拖拽）。
    -   **出码**：出码结果中能看到对应 props 被正确输出（类型/大小写/命名符合主工程组件 props 约定）。
    -   **预览**：预览行为与主工程运行态语义一致；若画布为“演示映射”（如用 `skeletonNum` 控制演示行数），需保证不改变运行态语义，并在文档中写清差异点。

### 1.5 导入与验证顺序

-   **先**在设计器中导入并验证 **MR 原子组件**（能拖拽、能显示、能使用），**再**验证依赖它们的 **MP 业务组件**，避免因原子依赖缺失导致业务组件报错或无法渲染。

### 1.6 VSCode 插件注入 URL 的启动加载约定（本次结论）

> 适用场景：插件侧已拿到远程物料 URL（如 `http://localhost:3000/bundle.json`），希望**打开设计器即看到可拖拽物料**，不依赖手动控制台刷新。

-   **根因**：仅依赖启动时一次性读取 `window.TINY_MATERIAL_BUNDLE_URLS` 不稳定；在某些 webview 时序下，`engine.service.resource/material` 尚未就绪，导致“URL 正确但未真正写入 store 与 componentsDeps”。
-   **稳定做法**：在 `appCreated` 阶段增加短周期自动重试；优先调用 `resource.fetchResource`，并在同轮追加一次“按 `bundleUrls` 强制拉取 + `material.addMaterials` + `updateCanvasDeps`”。
-   **目标行为**：即使启动瞬间 service 未就绪，也会在重试窗口内自动完成加载；用户打开设计器即可看到 `MR Components / MP Components` 等分组并可直接拖拽。
-   **排障口径**：
    1. `bundleUrls` 包含远程 URL；
    2. 启动后面板出现远程分组（如 MR/MP）；
    3. 画布侧 `componentsDeps` 同时包含内置与远程组件（不是只剩 mock/bundle）。
-   **工程约束**：此链路解决的是“启动时序与加载触发”问题，不替代后续 Asset Manager 正式协议（增删资产后的实时推送可继续走消息机制）。

## 二、经验总结：mr-img 画布不显示（避免踩雷）

### 2.1 现象

-   物料面板中的「Image」对应业务组件 **MpImage**；拖到画布并设置 `src` 后，**图片不显示**。
-   主工程中 **mr-img** 被大量使用（如 mp-image、fx-popup、search-item 等），对应的是 **Ionic 的 ion-img**。

### 2.2 原因归纳

| 要点                    | 说明                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **物料 vs 依赖**        | MrDivider 是**物料**（面板可拖拽），实现来自 Vant；**mr-img 是 MpImage 等组件的内部依赖**，不是独立物料。主工程里 `<mr-img>` = Ionic 的 ion-img。                             |
| **为何 MrDivider 能用** | Vant Divider 为纯 DOM + CSS，无 Ionic；画布加载 mr 入口后即可渲染。                                                                                                           |
| **为何 mr-img 不显示**  | 若设计器**未引入 Ionic**，或 mr 统一入口**只从 Vant 导出 MrImage/MrImg**（Vant Image），则画布内 MpImage 用到的 mr-img 与主工程不一致，且 Ionic 的 ion-img 未加载，无法渲染。 |

### 2.3 正确做法（符合规则）

1. **mr-components.js**：**引入 Ionic**，并导出主工程实际用作 mr-img 的组件为 `MrImg`。若 `ion-img` 在 `src` 为空时不可见，可对 `MrImg` 做“设计态包装”：无 `src` 输出占位，有 `src` 仍渲染真实 `IonImg`。
2. **设计器**：依赖中加入 Ionic，画布 iframe 内注入 Ionic 的脚本与样式。
3. **物料**：在 bundle 的 `components` 中为 MrImg 增加一条（与 MrDivider 同模式），使面板可拖拽、画布可用。
4. **不做**：不为 mr-img 造“另一个实现”去替代第三方组件（例如完全改成原生 `<img>` 并自行维护一套行为/样式）。占位包装仅用于设计态可见性与可选中，真实渲染仍以第三方组件为准。

### 2.4 参考代码（主工程 mr 入口）

```javascript
// 原子组件统一入口：从 Vant、Ionic 按 mr 命名 re-export。
// 主工程用哪个库的原子就用哪个，设计器依赖需同时包含 Vant 与 Ionic。

import {
    Divider,
    Progress,
    Field,
    ActionSheet,
    Image as VantImage,
    DatePicker
} from 'vant';
import { IonImg } from '@ionic/vue'; // 或主工程实际使用的 Ionic 图片组件路径

export { Divider as MrDivider };
export { Progress as MrProgress };
export { Field as MrField }; // 底层仍导出供 mp-input 等封装使用；物料层面请使用 MpInput，勿再使用 MrField 物料
export { ActionSheet as MrActionSheet };
export { VantImage as MrImage };
export { IonImg as MrImg }; // 主工程 <mr-img> 对应 Ionic，必须导出供画布与业务组件一致
export { DatePicker as MrDatePicker };
```

若主工程对 Ionic 组件有二次封装（如自定义 mr-img 封装件），此处应 export 该封装件，与主工程 resolver 一致。

## 二（续）、经验总结：MpImage 画布不可见/相对路径不生效（已修复）

### 现象

-   拖拽 `MpImage` 到画布后**没有占位**，导致在画布上难以直接选中。
-   给 `src` 设置图片地址（尤其是相对路径如 `./imgs/xxx.png`）后，画布仍**不显示图片**；但出码/预览正常。

### 原因归纳

-   **运行时组件不适合画布直用**：`src/components/base/mp-image.vue` 偏运行时语义，设计态在画布 iframe 中可能出现“无 src 时 0 尺寸/不可见”的问题。
-   **画布是 `iframe(srcdoc)`**：相对 URL 不会按业务页面的 base 解析，容易出现“预览正常、画布不显示”的错位。

### 正确做法（符合规则，主工程产物模式）

1. **主工程 entry 改为导出设计时兼容版**  
   在 `mobilebanking/lowcode-materials/entries/mp-image.js` 中，与 `mp-input` 一致，导出 `design-components/mp-image-designer.vue` 作为 `MpImage`，用于画布渲染。

2. **设计时兼容版必须满足两条硬标准**

    - **无 src 也可见可选中**：渲染占位（最小宽高/虚线框/文案）或至少保证容器 `min-height`。
    - **相对 src 可在画布生效**：在设计时组件内将 `./imgs/...`、`/imgs/...` 按 `window.location.origin` 归一化为可访问的绝对地址（因为画布是 srcdoc）。

3. **重新产出物料并让设计器加载**  
   主工程执行 `pnpm run build:designer-materials`，`serve dist/lowcode-materials` 后，设计器通过 bundle URL 加载即可生效；设计器无需内置/再产物料。

## 二（续）、经验总结：MpSelectList（选择列表）设计态图标与选中态对齐（已修复）

### 现象

-   `MpSelectList` 已导入到设计器，但画布上列表项左侧 **icon 被拉伸成“长条”**（高度异常），与预览/运行态不一致。
-   选中态最初用 `✓` 文本展示，与预览/运行态的 **radio 圆点** 观感不一致。
-   切换 `iconType` 为 `avatar/icon` 后，画布无法看到图片（只能看到首字母或占位），影响搭建时的“所见即所得”。

### 根因归纳

-   **组合组件依赖的设计态组件样式不适配“小图标场景”**：`MpSelectList` 设计态复用 `MpImageDesigner` 渲染图标；而 `MpImageDesigner` 默认容器存在 `min-height: 96px`，在 `iconSize=38` 且使用 `ratio="1"` 的情况下，会把图标区域撑高，导致图像被“拉成长条”的错觉。
-   **选中态实现策略不一致**：为了避免引入主工程图标依赖，最初用 `✓` 文本替代；但对 `SelectList` 来说 radio 圆点更符合预期，且可以用纯 CSS 实现，无需依赖 `i-*` 图标。
-   **iconType 的设计态目标不同于运行态**：运行态 `iconType=icon` 可能期望 Vue 图标组件；但设计态更重要的是“能看见”，因此允许用 `list[iconField]` 的图片地址来展示，缺省再回退占位。

### 正确做法（推荐实践）

1. **设计态组件保持“组合可用、可见优先”**  
   `mp-select-list-designer.vue` 继续复用 `mp-cell-designer.vue` + `mp-image-designer.vue`，并在 `iconType=image/avatar/icon` 三种情况下都优先尝试从 `list[iconField]` 渲染图片；无图时才回退首字母/占位。

2. **`MpImageDesigner` 在 `ratio` 场景取消默认 `min-height`**  
   当组件使用 `ratio`（例如 `ratio="1"`）时，容器高度应由比例盒子决定；避免默认 `min-height` 把“小图标”撑成大块区域。

3. **选中态用纯 CSS radio 圆点**  
   `MpSelectList` 选中态采用 18px 圆环 + 内圆点（`--mr-color-primary`），无需依赖 `i-mr-check` 或其它图标体系，画布与预览观感一致。

### list 参数建议（便于画布所见即所得）

最推荐每项包含：

-   `name`：展示字段（对应面板 `Display field`）
-   `value`：值字段（对应面板 `Value field`）
-   `desc`：描述字段（对应面板 `Desc field`）
-   `icon`：图标字段（对应面板 `Icon field`），建议填图片 URL（http(s)/以 `/` 开头的静态路径/`./` 相对路径）

示例：

```json
[
    {
        "name": "Option 1",
        "value": "1",
        "desc": "Description",
        "icon": "https://example.com/a.png"
    },
    {
        "name": "Option 2",
        "value": "2",
        "desc": "Description",
        "icon": "https://example.com/b.png"
    }
]
```

> 说明：设计态画布为 `iframe(srcdoc)`，相对路径会按 `window.location.origin` 归一化；请确保资源在当前服务域可访问。

## 二（续）、经验总结：MpTags 迁移全流程（代表性案例）

> **MpTags** 同时踩中「业务组件设计态」「manifest / 出码」「v-model state」「Ionic 画布桩 DOM 与全局样式」「运行态布局语义」等多条链路，迭代次数多，适合作为**标准对照**：后续类似「内部用 mr-segment / 列表可配置 / 需 v-model」的 MP 组件可复用本节检查清单。

### A. 架构原则（再次强调）

-   **物料只从主工程产出**：`lowcode-materials` 构建 bundle，设计器只加载 URL；**禁止**在设计器工程内造内置物料 JSON/JS 顶替主工程产物。
-   **不要为了设计态去改运行态业务源码**：`src/components/base/mp-tags.vue` 的 props/行为以主工程业务为准；画布差异用 **`design-components/*-designer.vue`** + **entry 指向 designer 版** 解决。

### B. 主工程物料（manifest + entry）

1. **`entries/mp-tags.js`**  
   导出 **`MpTags` = `design-components/mp-tags-designer.vue`**（与 `mp-image` / `mp-input` 同模式），画布走设计时实现，出码仍对应页面里的 `mp-tags` 标签（由引擎按物料名映射，以你们当前 bundle 协议为准）。

2. **`manifest.json`（MpTags）**

    - **`snippetSchema`**：`list` 用 **`JSExpression`**（数组字面量），避免出码丢选项；`modelValue` 用 **`JSExpression`** 绑定 `this.state.mpTagsN`（或占位名），属性面板才显示 **Bound**，而不是写死 `"1"`。
    - **`list`**：`schemaExtra` 里用 **CodeConfigurator**，`language: "javascript"` + **`dataType: "JSExpression"`**，兼容单引号/非严格 JSON 的编辑习惯；面板文案建议用 **List** 等清晰命名。
    - **`modelValue`**：同样 **`JSExpression`**，与 `mr-radio-group` 等「Group 类 v-model」一致。
    - **events**：声明 `onUpdate:modelValue` / `change` / `click` 等与运行态一致，便于事件面板绑定。
    - 修改 manifest 后必须 **`pnpm run build:designer-materials`**，设计器加载**新 bundle** 后再测（否则面板与 snippet 仍是旧逻辑）。

3. **设计时组件 `mp-tags-designer.vue`**
    - **解析 `list`**：`string`（JSON 或 JS 字面量）与 `array` 都要支持；`JSON.parse` 失败时用 **受控的 `new Function('return ('+s+')')()`** 仅作设计态兜底（与 CodeConfigurator 输出形态对齐）。
    - **内部仍用 `MrSegment` / `MrSegmentButton`**（来自 `@local/mr-components`），与主工程结构一致，避免再造一套交互。

### C. 设计器：state 与拖拽落盘（易错点）

-   **左侧 State 面板的数据来自页面根 `schema.state`**。与 **`MrSwitch` / `MrRadioGroup` / `MpTags` 等相同**：拖拽时自动创建 `state.xxx` 并绑定 `modelValue` 的入口在 **`container.ts` 的 `onMouseUp`**（外部拖入、`!sourceId`、合并 `generateNode` 默认 props 之后），具体实现已抽到 **`external-drop-handlers/`**（见下文 **I** 节）。**不是**只在 `useMaterial.ts` 的 `generateNode` 里写就能保证「一拖就有 state」。
-   新增同类组件时：在 **`external-drop-handlers`** 注册拖拽落盘逻辑，并视需要在 **`schema-default-patches`** 注册保存/预览兜底；**`patchSchemaWithMaterialDefaults`** 不能替代拖拽落盘时写入 state 的体验。

### D. 画布视觉：桩 ≠ ion-segment（易错点）

画布上的 **`MrSegment` / `MrSegmentButton` 来自 Ionic 画布桩**（如 `mr-segment-canvas.vue`），DOM 是 **`.mr-segment-stub` / `.mr-segment-button-stub`**，配套 **`mr-segment-stub-styles.js`** 与 **`injectDynamicCheckedStyle`** 的 **`::after` 下划线选中**，表现接近 **MD 分段**，与运行态 **`mp-tags.vue` 里真 `ion-segment` + module SCSS 胶囊** 不是同一套节点。

因此：

| 做法                                                                | 结论                                                                                                                                                                                     |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 在 `mp-tags-designer.vue` 里 `:deep(ion-segment)`、`::part(native)` | **画布上不生效**，易误判为「样式改不动」                                                                                                                                                 |
| 用 `:deep(.mr-segment-stub)`、`:deep(.mr-segment-button-stub)` 覆盖 | **正确方向**：胶囊圆角、边框、选中填充应对齐 `mp-tags.vue` 中变量（如 `--mr-color-button-bg-primary`、`--mr-color-button-border-tertiary`）                                              |
| 去掉桩的下划线                                                      | 覆盖 **`::after`**，并隐藏 **`.segment-button-indicator`**；必要时用 **`!important`** 压过动态注入样式                                                                                   |
| 子项被拉成三等分                                                    | 桩默认 **`flex: 1 1 0`**，需改为 **`flex: 0 0 auto`** 才像「多个标签」                                                                                                                   |
| 选中态 CSS                                                          | 桩带子节点时，动态 CSS 按 **`data-segment-value` / `data-value`** 配对；建议在按钮上用 Vue **`:class="{ 'segment-button-checked': ... }"`** 与 **`effectiveValue`** 对齐，选中样式才稳定 |

详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md) 中 **MrSegment / 画布 vs 出码** 小节。

### E. 设计态布局：不要照搬运行态负 margin

运行态 **`mp-tags.vue`** 使用 **`margin-left/right: calc(-1 * var(--mp-horizontal-padding))`** 抵消页面内容区内边距，让 segment **视觉顶满屏宽**。在设计器里节点选中框按**布局盒**计算，负 margin 会把 **`MpTags` 整节点向左拽出父级**，出现**选中边框左缘溢出画布**，而 **`MpCard` 等无负 margin 的组件正常**。

-   **设计态 `mp-tags-designer` 根容器**：不要使用这对负 margin；水平方向保持 **`max-width: 100%` + `box-sizing: border-box`**。
-   **运行态**仍保持主工程 `mp-tags.vue` 原逻辑，无需为设计器删减。

### F. 设计态垂直居中

根节点若仅设 **`min-height: 44px`** 且 **`display: block`**，内部 segment 会**贴顶**，选中框内下方留白。改为根容器 **`display: flex; flex-direction: column; justify-content: center; align-items: stretch`**，在保持**子级全宽**的前提下把标签行**垂直居中**。

### G. 依赖缺失（历史问题）

若拖到画布**不显示或报错**，先查 **`mr-components.js` 是否导出 `MrSegment` / `MrSegmentButton` / `MrLabel`**，bundle 是否包含对应物料条；桩实现与样式注入仍见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md)。

### H. 验收清单（MpTags 专用）

-   [ ] 拖拽后左侧 **State** 出现 **`mpTags1`**（或递增），**Selected Value** 为 **Bound: `this.state.mpTagsN`**。
-   [ ] 修改 **state** 或 **modelValue** 绑定，画布选中项与之一致。
-   [ ] **List** 面板修改后画布与出码均更新；**出码**无写死 `modelValue="1"`（应为 **v-model** 语义 + state）。
-   [ ] 画布标签为**胶囊**观感，**无 MD 下划线**；选中框**不左右溢出**父级；标签行在框内**垂直方向不悬空贴顶**。
-   [ ] **未改** `src/components/base/mp-tags.vue` 运行态接口来迁就设计器。

### I. 设计器代码组织：v-model 相关逻辑拆分（维护性）

为避免 `container.ts` / `useMaterial.ts` 被无限 `if (componentName === '…')` 撑长，将与 **「拖拽落盘建 state」**、**「保存/预览前补绑定」** 相关的逻辑拆成两处注册表，**行为与原先一致**，后续新组件按表扩展即可。

| 职责                                                                                                                          | 目录（均在 `designer-demo`）                                  | 入口 API                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 从物料面板**拖入画布**时注入 `state` + `modelValue`（`JSExpression` + `model: true`）                                         | `src/components/canvas/container/src/external-drop-handlers/` | `applyExternalDropComponentPatch`（由 `container.ts` `onMouseUp` 调用）                     |
| **预览/保存前**对整棵树兜底修正常量 `modelValue`、补缺失 state 字段；**`generateNode`** 阶段个别组件（如 MpTags）补页面 state | `src/plugins/materials/composable/schema-default-patches/`    | `applyModelBindingSchemaPatch`、`applyGenerateNodeModelPatches`（由 `useMaterial.ts` 调用） |
| **共用工具**（判断已绑定表达式、分配 `prefix1`/`prefix2`… state key，避免两处复制粘贴）                                       | `src/composable/modelBindingShared.ts`                        | `isModelValueJsExpression`、`allocateIndexedStateKey`                                       |

**新增需要 v-model 演示的组件时**：各写一个 handler / patch 文件，在对应目录的 **`HANDLERS` / `PATCHERS` 注册表**里增加 `组件名 → 函数` 即可；**不要**再往 `container.ts` / `useMaterial.ts` 主文件里堆长分支。与「常量改 `this.state.xxx`」相关的重复逻辑优先复用 **`modelBindingShared`**。

> 远期若要多主工程共用设计器，可把「组件名 → 行为」进一步改为 **物料 manifest 元数据驱动**，注册表只做默认实现；当前拆分已便于定位与 Code Review。

## 二（续二）、经验总结：MpMultiAmt 迁移经验（多币种金额）

> 本组件迭代次数多，根因是 **`mp-multi-amt` 同时踩中**：① 主工程**双具名 v-model** 与出码 **`model` 元数据协议**；② 设计器 **state 形态**与业务预览 **不一致**；③ **画布桩裸布局**与相邻 **`MrField` 画布桩**的横向基准不一致；④ **manifest 布尔默认值**与运行态 **`border: undefined`** 语义错位。以下按「一次对齐三条链」总结，避免后续同类组件再靠人肉反复试。

### A. 出码与 `model` 协议（硬错误）

-   运行态为 **`defineModel('payerVal')` + `defineModel('payeeVal')`**，出码须 **`v-model:payer-val` / `v-model:payee-val`**。
-   两个绑定都写 **`model: true`** 时，出码器会生成**两个普通 `v-model`**，Vue 编译报 **Duplicate attribute**。
-   **正确写法**：`{ type: 'JSExpression', value: 'this.state.…', model: { prop: 'payerVal' } }` 与 `model: { prop: 'payeeVal' }`（与 `ConfigItem` 内「非 `modelValue` 须 `{ prop: … }`」一致）。
-   设计器侧将落盘 / generateNode / 保存补丁收敛到 **`designer-demo/src/composable/mpMultiAmtDesignerBinding.ts`**，并在 **`external-drop-handlers`**、**`schema-default-patches`**、**`generateNodePatches`** 三处注册，避免逻辑分叉。

### B. `limitRule` 与 state 形态（代表性）

-   仅绑 **`payeeVal → this.state.mpMultiAmtN`** 不足以表达主工程常见页；应提供 **`payerVal` + `payeeVal` + `limitRule`** 与结构化 state（如 **`mpMultiAmtFormN.{payerAmount,payeeAmount}`** + **`mpMultiAmtLimitRuleN`**）。
-   若用户已手写 **`this.state.payBillInfo.*`** 等业务路径，**自动绑定逻辑须跳过**，避免覆盖出码。

### C. 画布桩与 `MrField` 对齐（视觉误导）

-   画布桩若为**裸根 `div` + 自绘灰底/下划线**，必须与 **`MrField`/`van-cell`** 使用**同一套横向 inset**（见上文 **「画布桩与相邻 `MrField` 横向基准（强规则）」**）：根级 `padding-left/right: var(--van-cell-horizontal-padding, var(--mp-horizontal-padding, 16px))`；灰底内文字再用**独立变量**（如 `--mp-amt-payer-inner-x`）控制，**禁止**根与灰底各套一层同名 token **叠乘**（否则要么灰框相对 Title **左凸**，要么框内文字离灰边**多一截**）。
-   **付款灰底**与 **收款下划线** 分层还原；金额与币种间距对齐 **`mp-single-amt` large** 的 **`ltr:ml-8px`**（画布约 **8px**）。
-   **`payeeLabel` / `label` 只来自 props**，不在桩内写死 **`Recipient will receive`**；`snippetSchema` 可显式带 **`payeeLabel: ""`** 便于面板配置。

### D. `manifest` 与运行态默认值

-   **`border`**：运行态常为 **`undefined`**，由子组件决定是否隐藏 hairline；若物料 **`defaultValue: false`**，画布易把收款下划线关掉而预览仍有线。**不要**对 `border` 写死 **`defaultValue: false`**；由用户或 snippet 显式配置。
-   **`snippetSchema`** 应体现 **`payerVal`/`payeeVal`/`limitRule`** 等主工程高频 props；改 manifest 后主工程执行 **`pnpm run build:designer-materials`**。

### E. 验收清单（MpMultiAmt）

-   [ ] 拖入后出码为 **`v-model:payer-val` / `v-model:payee-val`**，无 **`v-model` 重复**。
-   [ ] 画布上灰底、汇率行、收款行与 **Title / Mobile Number** **左右对齐**；收款行**默认有底划线**（除非用户显式配置与运行态一致的关闭语义）。
-   [ ] 属性面板 **`size` / `labelAlign` / `inputAlign` / `border`** 在桩内有可见反馈（或文档说明与运行态差异）。
-   [ ] **`payeeLabel`** 仅展示传入值，无桩内写死英文句子。

## 二（续）、经验总结：MpCell 迁移经验（列表单元格）

> **MpCell** 与 **MpImage** 同属「运行态依赖全局样式/图标，画布 iframe 里易残」的类型，但**不需要 v-model**，也**不必**改 `container.ts` / `external-drop-handlers`；重点在 **designer 版 + manifest 补全 + 与运行态视觉默认对齐**。

### A. 为何不能直出运行态组件

-   运行态 `src/components/base/mp-cell.vue` 使用 **Uno/Tailwind 式 utility class**（如 `flex`、`items-center`）、**`mp-icon` + 图标组件**，以及 **`<style module lang="scss">`** 的 hairline；在设计器画布（常缺同一套原子类与图标注册）里容易出现**不可见、难选中、箭头缺失**。
-   原则与 MpTags / MpImage 一致：**不要为迁就设计器改运行态业务接口**；画布用 **`lowcode-materials/design-components/mp-cell-designer.vue`**，**`entries/mp-cell.js`** 导出 **`MpCellDesigner as MpCell`**。

### B. 设计时组件要点（`mp-cell-designer.vue`）

-   **自包含布局**：`display: flex`、`min-height`、标题/描述字号与间距用 **scoped CSS**，不依赖 Uno。
-   **`isLink` 箭头**：用简单字符 **`›`** 或内联样式模拟，**避免**依赖 **`mp-icon`**，以免画布再挂一条图标物料链。
-   **插槽与运行态一致**：`start` / `title` / `desc` / `end`，便于出码与结构理解；`manifest` 里 **`isContainer: true`** + **`schemaExtra.slots`** 声明四个具名插槽。
-   **顶部分割线（易踩坑）**：运行态 hairline 为  
    `border-top: var(--mp-cell-border-width, 0) solid …`，**默认线宽为 0**。若在 designer 里用 `::after` 写死 `1px border-top`，画布会**多出一条预览/出码没有的横线**；设计态应**默认不画顶线**，与运行态默认一致。

### C. `manifest.json`（MpCell）

-   **`snippetSchema.props`**：提供拖拽默认文案；设计器语言为英文时应用 **`Title`**、**`Description`**（勿用中文占位「标题」「描述文案」），避免与面板语言不一致。
-   **`schemaExtra`**：`title` / `desc` / `isLink` / `gap` / `testId` 等属性面板字段；**`events.onClick`**（设计态根节点可 `$emit('click')` 便于绑事件）。
-   修改后主工程执行 **`pnpm run build:designer-materials`**，设计器通过 **远程 bundle URL**（如主工程静态服务）加载新产物。

### D. 与 MpTags 的差异（不必做的部分）

-   **无 `v-model` 演示需求**时：无需在 **`external-drop-handlers`** / **`schema-default-patches`** 为 MpCell 注册与 state 相关的补丁。
-   **不修改**运行态 `mp-cell.vue` 的 props/结构来迁就画布。

### E. bundle 与 mock 的边界（协作约定）

-   **`designer-demo/public/mock/bundle.json`**（若存在）与 **主工程 `dist/lowcode-materials/bundle.json`** 是**两套用途**：mock 多为离线/基线快照；主工程产物通过 **URL** 联调。**不应**在无人明确要求时把构建产物 **`cp` 覆盖进 mock**，避免把「联调物料」与「内置 mock」混成一份、产生无意义大 diff 或误覆盖团队基线。

### F. 验收清单（MpCell）

-   [ ] 物料面板拖入后画布**可见、可选中**，标题/描述默认英文 snippet 正确。
-   [ ] **无**多余顶部分割线（与预览/运行态默认一致）。
-   [ ] `isLink` 时右侧有**可读箭头**，不依赖画布内再拖 `mp-icon`。
-   [ ] 属性面板字段与 **slots** 分组可用；出码仍为 **`MpCell` / `mp-cell`** 语义（以当前 bundle 协议为准）。
-   [ ] **未**为设计态改写运行态 `mp-cell.vue` 业务实现。

## 二（续）、经验总结：MpIcon（图标容器）迁移经验（B 方案：画布占位 + 出码保持 i-\*）

> 主工程 `mp-icon` 的常规用法是 **`<mp-icon ...><i-collection-icon /></mp-icon>`**。其中 `i-*` 标签来自主工程的图标生成机制（如 unplugin-icons），设计器**不应**强耦合主工程源码目录去生成这些组件。最佳实践是：**画布只做占位可见**，并在**出码/预览时把“图标标签名”翻译成真实的 `<i-*>` 子节点**，从而保持出码与主工程机制一致。

### A. 现象

-   设计器画布中拖入 `MpIcon`，若直接渲染运行态 `<slot><i-.../></slot>`，由于设计器未注册 `i-*` 组件，会出现**不显示/报 unknown component**。
-   即使在属性面板填了 `iconTag="i-mr-more"`，运行态 `mp-icon.vue` 并不认识该 prop，出码后仍可能**不显示图标**。

### B. 原则（最重要）

-   **画布可见性 ≠ 出码可用性**：画布仅需“可选中、可布局、可配置”，不必在画布内真实渲染所有 svg。
-   **出码必须回到主工程机制**：最终输出仍为 `<mp-icon><i-xxx-yyy /></mp-icon>`，由主工程的图标体系解析 svg。

### C. 正确做法（B 方案）

1. **主工程物料改 entry，画布用 designer 版**

    - `entries/mp-icon.js` 导出 `MpIconDesigner as MpIcon`
    - `design-components/mp-icon-designer.vue` 仅渲染**中性占位**（圆角方块），支持 `size/color`，避免误导为某个具体图标

2. **manifest 仅暴露“图标标签名”配置**

    - `schemaExtra.properties` 增加 `iconTag`（InputConfigurator）
    - `snippetSchema` 默认 `iconTag: "i-mr-more"`（英文默认）
    - （更新）设计器已全局不注入并剥离 `component-base-style`，无需再为 `MpIcon` 单独维护“跳过 base-style”逻辑

3. **出码/预览前把 iconTag 翻译成子节点 `<i-*>`**
    - 设计器补丁应将 `props.iconTag` 转为 `children[0].componentName = iconTag`
    - **同时删除 `props.iconTag`**（运行态 mp-icon 不识别，保留会导致预览不显示）

### D. 易踩坑（这次踩过）

-   **补丁挂错入口导致出码无效**：仅在“保存/预览前 patch”里改 schema 不一定覆盖工具栏“出码”路径。更稳做法是在 `useCanvas().getSchema()`（所有出码/保存/预览都要取 schema）处兜底，把 MpIcon 统一归一化。
-   **大小/颜色不生效**：画布占位需用 `font-size`（由 `mp-icon` 约定）驱动尺寸，且必须确保设计器加载到最新 bundle（旧节点可能仍是运行态组件）。

### E. 验收清单（MpIcon）

-   [ ] 画布拖入后**可见可选中**（中性占位，不占满宽度）。
-   [ ] 属性面板 `size/color` 调整对画布占位**立即生效**。
-   [ ] 出码/预览生成 **`<mp-icon ...><i-xxx-yyy /></mp-icon>`**。
-   [ ] 出码中不出现无效的 `iconTag="..."` 属性。

## 二（续）、经验总结：MrSegment 属性与出码

### 现象与规则

| 要点                                  | 说明                                                                                                                                                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **value 即 v-model**                  | MrSegment 的 value 对应主工程 v-model，物料 events 需配置 `onUpdate:value`。                                                                                                                            |
| **子按钮 value 唯一**                 | 每个 MrSegmentButton 的 value 不能重复，否则出码后会出现多个按钮同时选中。                                                                                                                              |
| **MrSegmentButton 不设 defaultValue** | manifest 中 MrSegmentButton 的 value 不要设 defaultValue，避免覆盖 snippet 中的默认值。                                                                                                                 |
| **出码前 value 修正**                 | 在 `patchSchemaWithMaterialDefaults` 中为 MrSegment 子按钮做 value 唯一性修正（重复或空时按 default、segment、button、tab1… 分配）。                                                                    |
| **画布 value 同步**                   | 属性面板修改 value 后，画布桩可能不实时同步选中态（已知限制）；出码和预览不受影响。                                                                                                                     |
| **子按钮对齐**                        | MrSegmentButton 是 ion-segment 的 flex 子项，额外 margin 会破坏对齐。当前设计器已全局不注入并剥离 `component-base-style`，因此无需再依赖跳过列表；若仍错位，应检查桩自身 flex 样式或子按钮 value 配置。 |
| **最低要求**                          | 属性可配置 + 出码正确；画布实时同步为可选优化。                                                                                                                                                         |

### 正确做法

1. **manifest**：MrSegment 保留 value、scrollable、disabled、mode；value 的 defaultValue 为 `"default"`；events 含 `onUpdate:value` 和 `onIonChange`。
2. **MrSegmentButton**：value 不设 defaultValue；snippet 中为每个按钮显式指定唯一 value。
3. **useMaterial**：在 `patchSchemaWithMaterialDefaults` 中检测 MrSegment 子按钮，对重复或空 value 做自动修正。

-   遇到 **MpDictText 画布空白或运行态 dict 不可用**时：对照 **「MpDictText 迁移经验」**——运行态依赖 **Pinia `useDictStore`**，设计器 runtime 未挂该 store 时应使用 **`mp-dict-text-designer.vue`**（内置少量演示映射 + 回退显示 `fieldValue`）；出码仍为 **`mp-dict-text`**。

## 二（续）、经验总结：MpResult（结果页）迁移经验（图标资源随物料输出）

> **MpResult** 运行态内部依赖 `mp-icon + <i-mr-success/pending/failed />`、`v-test-id` 指令以及主工程的 utility class；直接在画布渲染运行态组件容易因依赖缺失导致“不显示/报错/样式错位”。因此与 MpCell/MpIcon 同原则：**画布走 designer 兼容版**，出码仍保持运行态标签语义。

### A. 正确做法（主工程物料侧）

1. **新增设计态组件**：`lowcode-materials/design-components/mp-result-designer.vue`

    - 仅实现画布所需的最小展示：`type/title/desc`
    - 图标不依赖 `mp-icon/i-*`，而是复用主工程 `src/assets/icons/{success,pending,failed}.svg`

2. **entry 指向 designer 版**：`lowcode-materials/entries/mp-result.js`

    - `export { MpResultDesigner as MpResult }`

3. **manifest 配置**：`lowcode-materials/manifest.json`
    - `snippetSchema` 默认英文（如 `Result Title/Result description`）
    - 属性面板提供 `type(success/pending/failed)`、`title`、`desc`

### B. 关键坑：SVG 外链 `<img src="*.svg">` 不继承 CSS 变量

这次踩到的点是：主工程的结果图标 SVG 使用了主题变量（如 `var(--mr-color-success)`）。  
若设计态用外链方式渲染：

-   `<img :src="xxx.svg">`

浏览器不会把页面的 CSS 变量传递进外链 SVG 文档，导致 `fill/stroke` 解析失败，视觉上就像“图标不显示”。

**正确方式**是在设计态把 SVG **内联**到当前 DOM：

-   `import successSvgRaw from '.../success.svg?raw'`
-   `v-html` 渲染 raw 字符串（并限制来源只来自仓库内的受控资源）

这样 SVG 就能正常读取画布里的 `--mr-color-*`，视觉与运行态更接近。

### C. 验收清单（MpResult）

-   [ ] 画布拖入后**可见可选中**，默认文案为英文。
-   [ ] 切换 `type`（success/pending/failed）图标与色彩随之变化（依赖 `--mr-color-*`）。
-   [ ] 属性面板 `title/desc` 可改，画布及时更新。
-   [ ] 出码仍为运行态 `mp-result`，不引入 `mp-result-designer`；运行态图标仍走 `mp-icon + i-*` 机制。

## 二（续）、经验总结：MpDictInput（字典输入）标题缺失与边界约束

> **MpDictInput** 导入后出现过“预览只显示一行值、标题不显示”的问题。根因并非组件不可用，而是**出码省略了 props 默认值**与运行态组件无回退文案叠加导致。此类问题要优先在**物料层**修复，禁止改主工程运行态源码来迁就设计器。

### A. 现象

-   设计器画布里可见（`mp-dict-input-canvas` 有标题占位），但预览中未配置 `label` 时只显示一行值。
-   设置 `dictName` 后值可正常回显，仍可能无标题，容易误判为“dict 接口问题”。

### B. 根因

-   运行态 `mp-dict-input.vue` 模板直接使用 `label/placeholder`，无兜底回退；
-   低代码出码会省略“等于默认值”的 props；
-   若物料默认值配置不当，最终出码可能缺少 `label/placeholder`，预览就看不到标题。

### C. 正确修复方式（本次结论）

1. **不改主工程运行态组件源码**（边界硬约束）。
2. 在 `lowcode-materials/manifest.json` 的 `MpDictInput` 条目中：
    - 用 `snippetSchema.props` 显式写入 `label/placeholder/labelAlign`；
    - `schemaExtra` 的 `label/placeholder` `defaultValue` 置空，避免被误判后省略关键展示 props。
3. 设计态仍使用 `mp-dict-input-canvas.vue` 做可见占位与交互演示；v-model 绑定继续走 `external-drop-handlers + schema-default-patches + generateNode` 三处兜底。

### D. 验收清单（MpDictInput）

-   [ ] 预览：未手工改 label 时仍显示标题；设置 `dictName` 后值与标题同时可见。
-   [ ] 边界：主工程 `src/components/dict/mp-dict-input.vue` 无为设计器导入而做的运行态改造。

## 二（续）、经验总结：MrInfiniteScroll 画布占位与事件绑定

### 规则要点

| 要点                       | 说明                                                                                                                                                                                                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **画布占位必须可见**       | 画布桩需设置 `min-height`、slot 默认内容，确保组件拖入后始终有可见占位，便于定位与调整；否则易出现「树里有、画布看不见」导致位置放错。                                                                                                                            |
| **snippet 不设事件默认值** | 若在 snippetSchema.props 中写死事件 handler（如 `onIonInfinite: { value: "(evt) => evt.target.complete()" }`），会覆盖用户在「高级」→「事件绑定」中的绑定，出码仍用 snippet 默认而非用户方法。**正确做法**：snippet 只设属性默认（如 disabled），事件由用户绑定。 |
| **事件绑定方法注释**       | 对需在 handler 内调用特定 API 的事件（如 onIonInfinite 需 `evt.target.complete()`），可在设计器 `BindEventsDialog` 的 `rewriteMethodParams` 中，当 `eventName === 'onIonInfinite'` 且为新建方法时，注入默认注释体，提醒开发者完善逻辑后调用 complete。            |
| **固定父子结构**           | 若组件用法固定（如 mr-infinite-scroll 必包 mr-infinite-scroll-content），manifest 配置 `snippetSchema.children` 包含子节点，子组件设 `hiddenInPanel: true`，拖入即带完整结构。                                                                                    |

### 正确做法

1. **画布桩**：`mr-infinite-scroll-canvas.vue` 使用 `min-height`、`<slot>Loading...</slot>` 默认内容；样式 `mr-infinite-scroll-stub-styles.js` 中 `.mr-infinite-scroll-stub`、`.mr-infinite-scroll-content-stub` 均设 `min-height`。
2. **manifest**：snippetSchema.props 仅含 `disabled: false`，不含 `onIonInfinite`；schemaExtra.events 声明 `onIonInfinite`，并加 description 说明需调用 `evt.target.complete()`。
3. **设计器**：在 `designer-demo/src/settings/events/components/BindEventsDialog.vue` 的 `rewriteMethodParams` 中，当 `props.eventBinding?.eventName === 'onIonInfinite'` 且 `!method` 时，defaultBody 使用带注释的函数体。
