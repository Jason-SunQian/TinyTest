# 组件导入注意事项

本文档约定**组件导入与设计时兼容的规则**，后续执行（新增原子/业务组件、排查画布不显示等）均应在这些规则下进行；并收录**经验总结**，避免重复踩雷、便于他人查阅。

---

## 一、组件导入规则（必须遵守）

### 1.1 原子组件（MR 开头）

-   **默认一律使用第三方库源码**（Vant / Ionic），不手写“另一个实现”来替代原子组件。
-   主工程用哪个库的原子（Vant 还是 Ionic），设计器就提供哪个：该用 Vant 用 Vant、该用 Ionic 用 Ionic，与主工程 resolver 命名一致。
-   在主工程中被**高频使用**的原子（如 mr-img），应作为**物料**在面板中展示并可拖拽，且使用**真实实现**（主工程用 Ionic 的 ion-img 就导出 Ionic 的 MrImg），不得用「原生 `<img>` + 手写 CSS」等桩替代。
-
-   **允许的最小“设计态包装”例外（推荐做法）**：当第三方原子组件在缺少关键 prop（如 `src`）时会出现**0 尺寸/不可见**，导致画布“拖进来啥也看不到、选不中”时，可以在物料入口对该原子做一个**轻量包装**：
    -   `src` 等关键 prop **有值**：仍渲染**真实第三方组件**（保持与主工程一致）
    -   关键 prop **无值**：渲染一个**可见占位 DOM**（设置 `minWidth/minHeight`、边框/背景/提示文本），确保可选中/可配置
    -   该包装必须是**同名导出**（如仍导出 `MrImg`），且逻辑尽量简单，避免引入大量自定义样式与复杂行为

### 1.2 设计器环境与依赖

-   设计器与主工程一致地**同时引入 Vant 和 Ionic**；设计器依赖中必须包含 Ionic（与主工程同版本或兼容版本），画布 iframe 内注入两者的脚本与样式。
-   画布内「该用哪个就用哪个」：组件从 mr 统一入口按主工程 resolver 导出，设计器只负责提供完整运行时与样式。

### 1.3 业务组件（MP 开头）

-   **优先使用主工程源码**；能通过「设计器引入 Vant + Ionic + 提取主工程样式」正常显示的，不造桩。
-   **仅**在以下情况才为业务组件做设计时桩（原生标签 + 手写 CSS）：
    -   该组件**极其复杂**，或
    -   在画布上**即使用完整依赖也无法正常表现**。
-   做桩时需考虑**降低维护成本**：尽量使用通用脚本/模板，避免每个组件从零手写大量 CSS。

### 1.4 样式与物料配置

-   主工程对 **Vant** 的样式覆盖应通过**提取全局样式**在设计器中使用，保证画布与主工程视觉一致。
-   **Ionic 组件**：提取样式对画布无效（Shadow DOM 导致外部 CSS 无法穿透），需采用**桩 + 样式自注入**，详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md)。
-   **Ionic 桩的 v-model 协议**：若组件有 value 绑定（如 MrSegment），manifest 的 events 需配置 `onUpdate:value`；子组件（如 MrSegmentButton）的 value 必须唯一，出码前由 `patchSchemaWithMaterialDefaults` 做唯一性修正。
-   **ion-segment 内按钮对齐**：在 `constants.ts` 配置 `COMPONENTS_SKIP_BASE_STYLE`，useMaterial 与 container 据此排除 component-base-style。
-   每个需要在面板拖拽的原子组件，在 bundle 的 `components` 中必须有对应物料条（`component`、`npm.script`、`npm.exportName` 等），与 MrDivider 的配置方式一致。
-   **视觉反馈类组件（强规则）**：如 `mr-progress-bar`、`mr-switch`、`mr-checkbox` 等，画布桩必须优先复用运行态同源主题变量（如 Ionic CSS 变量），禁止长期使用“示意色/临时色”替代真实视觉；否则会误导配置判断，导致“画布看起来对、出码效果不对”。
-   **视觉反馈类组件验收标准（必须同时满足）**：① 颜色/主题跟随运行态变量；② 关键尺寸（高度、圆角、描边粗细）与运行态同量级；③ 关键状态（默认/激活/禁用/加载）在画布中可识别且与出码语义一致。
-   **高频循环组件（推荐规则）**：若某组件在主工程高频以循环渲染使用（如 `mr-collapse-item`），允许在拖拽阶段注入“可回退的循环模板”（`loop/loopArgs/key` + 示例 state 列表），确保用户拖拽后立即看到循环效果。模板必须可一键改回普通节点（清空 loop）且不影响手工配置。
-   **组合交互组件（强规则）**：若组件必须与子组件配合才有功能（如 `mr-item-sliding` 需 `mr-item-options`/`mr-item-option`），`snippetSchema` 必须提供“拖拽即用”的完整最小示例，并在 `nestingRule` 中限制父子结构，避免用户拖入后看不到交互或结构搭错。
-   **多 item 结构组件（强规则）**：`mr-reorder-group`、`mr-cell-group` 这类真实场景常包含多条 item 的组件，`snippetSchema` 不可只给空壳或单项，必须默认提供 2~3 条示例并体现差异化配置（如 `isLink`），确保拖拽后立即看懂结构与配置入口。
-   **Reorder 交互闭环（强规则）**：`mr-reorder-group` 的事件处理必须调用 `event.detail.complete()`；若仅绑定事件而未完成回调，运行态会出现拖拽后卡住，误导为组件不可用。
-   **列表类桩视觉一致性（强规则）**：`mr-item`/`mr-item-sliding` 等列表组件的画布桩背景、边框、圆角必须对齐运行态；背景优先走 Ionic 变量链（`--background -> --ion-item-background -> --ion-background-color`），禁止额外装饰（如运行态不存在的圆角/外框）造成误导。
-   **Group 选择类组件 v-model（强规则）**：`mr-radio-group`、`mr-checkbox-group`、`mr-collapse`、`mr-switch` 等依赖双向绑定的组件，禁止以常量 `modelValue` 作为默认可运行示例；必须在拖拽落盘与保存/预览补丁阶段自动改写为 `JSExpression + model:true` 绑定 `this.state.xxx`，并自动创建对应 state（单选默认首项、多选默认数组），保证“拖拽即能点击交互”。
-   **表单字段 v-model（强规则）**：`mr-form` 下应使用 **`MpInput`（mp-input）** 作为输入项（不再推荐使用物料 `MrField`）；必须把 **`modelValue` 绑定到页面根 `state` 的嵌套字段**（如 `this.state.mrForm1.email`），否则设计态输入会在重渲染后丢失、校验仍像未填；拖拽 `MrForm` 时应自动创建 `state.mrFormN` 对象并为各 `MpInput` 写入绑定。`patchSchemaWithMaterialDefaults` 递归时必须共享**根 schema 的 `state` 引用**，避免在子节点上把补丁写到空 `state`。面板需暴露 `MpInput` 的 `modelValue` 以及 `name` / `rules`（与 `mr-form` 校验一致）。历史 schema 中若仍含 `MrField`，保存前补丁会一并处理。
-   **MpInput 的 `complete` 与主工程一致**：主工程常在 `mr-form` 里对每个 `mp-input` 绑定 `@complete`，在回调里根据 **多处字段** 或接口结果汇总校验，再 **`emit('validate', true/false)`** 或写 **`state`** 控制「下一步/提交」按钮。设计器物料已为 `MpInput` 注册 **`onComplete`**（出码为 `@complete`）；设计器桩在 **失焦** 时也会触发 `complete`，便于演示。默认 `MrForm` 片段会绑定 **`this.onDemoFormRecalculateSubmit`**（根据 `this.state[this.state.demoFormTargetKey]` 聚合校验并设置 **`formDemoSubmitEnabled`**）及 **`onSubmit` → `this.onDemoFormSubmit`**（把 Vant 提交的 **`values` 写入 `formDemoLastSubmit`**）；拖拽 `MrForm` 时若页面尚无这两个方法会自动写入 **`methods`**。多表单场景请自行区分 `demoFormTargetKey` 或改为独立方法。
-   **slot 文本回显一致性（强规则）**：`MrLabel`、`MrButton`、`MrToggle` 这类“文本存于 `children`”的组件，必须在属性面板读取前执行 `children <-> props.children` 同步；若二者冲突，一律以 `schema.children` 为真值源回写 `props.children`，避免“画布/出码生效但二次选中回显旧值”。

### 1.5 导入与验证顺序

-   **先**在设计器中导入并验证 **MR 原子组件**（能拖拽、能显示、能使用），**再**验证依赖它们的 **MP 业务组件**，避免因原子依赖缺失导致业务组件报错或无法渲染。

## 二、经验总结：mr-img 画布不显示（避免踩雷）

### 2.1 现象

-   物料面板中的「Image」对应业务组件 **MpImage**；拖到画布并设置 `src` 后，**图片不显示**。
-   主工程中 **mr-img** 被大量使用（如 mp-image、fx-popup、search-item 等），对应的是 **Ionic 的 ion-img**。

### 2.2 原因归纳

| 要点                    | 说明                                                                                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **物料 vs 依赖**        | MrDivider 是**物料**（面板可拖拽），实现来自 Vant；**mr-img 是 MpImage 等组件的内部依赖**，不是独立物料。主工程里 `<mr-img>` = Ionic 的 ion-img。                             |
| **为何 MrDivider 能用** | Vant Divider 为纯 DOM + CSS，无 Ionic；画布加载 mr 入口后即可渲染。                                                                                                           |
| **为何 mr-img 不显示**  | 若设计器**未引入 Ionic**，或 mr 统一入口**只从 Vant 导出 MrImage/MrImg**（Vant Image），则画布内 MpImage 用到的 mr-img 与主工程不一致，且 Ionic 的 ion-img 未加载，无法渲染。 |

### 2.3 正确做法（符合规则）

1. **mr-components.js**：**引入 Ionic**，并导出主工程实际用作 mr-img 的组件为 `MrImg`。若 `ion-img` 在 `src` 为空时不可见，可对 `MrImg` 做“设计态包装”：无 `src` 输出占位，有 `src` 仍渲染真实 `IonImg`。
2. **设计器**：依赖中加入 Ionic，画布 iframe 内注入 Ionic 的脚本与样式。
3. **物料**：在 bundle 的 `components` 中为 MrImg 增加一条（与 MrDivider 同模式），使面板可拖拽、画布可用。
4. **不做**：不为 mr-img 造“另一个实现”去替代第三方组件（例如完全改成原生 `<img>` 并自行维护一套行为/样式）。占位包装仅用于设计态可见性与可选中，真实渲染仍以第三方组件为准。

### 2.4 参考代码（主工程 mr 入口）

```javascript
// 原子组件统一入口：从 Vant、Ionic 按 mr 命名 re-export。
// 主工程用哪个库的原子就用哪个，设计器依赖需同时包含 Vant 与 Ionic。

import {
    Divider,
    Progress,
    Field,
    ActionSheet,
    Image as VantImage,
    DatePicker
} from 'vant';
import { IonImg } from '@ionic/vue'; // 或主工程实际使用的 Ionic 图片组件路径

export { Divider as MrDivider };
export { Progress as MrProgress };
export { Field as MrField }; // 底层仍导出供 mp-input 等封装使用；物料层面请使用 MpInput，勿再使用 MrField 物料
export { ActionSheet as MrActionSheet };
export { VantImage as MrImage };
export { IonImg as MrImg }; // 主工程 <mr-img> 对应 Ionic，必须导出供画布与业务组件一致
export { DatePicker as MrDatePicker };
```

若主工程对 Ionic 组件有二次封装（如自定义 mr-img 封装件），此处应 export 该封装件，与主工程 resolver 一致。

## 二（续）、经验总结：MpImage 画布不可见/相对路径不生效（已修复）

### 现象

- 拖拽 `MpImage` 到画布后**没有占位**，导致在画布上难以直接选中。
- 给 `src` 设置图片地址（尤其是相对路径如 `./imgs/xxx.png`）后，画布仍**不显示图片**；但出码/预览正常。

### 原因归纳

- **运行时组件不适合画布直用**：`src/components/base/mp-image.vue` 偏运行时语义，设计态在画布 iframe 中可能出现“无 src 时 0 尺寸/不可见”的问题。
- **画布是 `iframe(srcdoc)`**：相对 URL 不会按业务页面的 base 解析，容易出现“预览正常、画布不显示”的错位。

### 正确做法（符合规则，主工程产物模式）

1. **主工程 entry 改为导出设计时兼容版**  
   在 `mobilebanking/lowcode-materials/entries/mp-image.js` 中，与 `mp-input` 一致，导出 `design-components/mp-image-designer.vue` 作为 `MpImage`，用于画布渲染。

2. **设计时兼容版必须满足两条硬标准**  
   - **无 src 也可见可选中**：渲染占位（最小宽高/虚线框/文案）或至少保证容器 `min-height`。
   - **相对 src 可在画布生效**：在设计时组件内将 `./imgs/...`、`/imgs/...` 按 `window.location.origin` 归一化为可访问的绝对地址（因为画布是 srcdoc）。

3. **重新产出物料并让设计器加载**  
   主工程执行 `pnpm run build:designer-materials`，`serve dist/lowcode-materials` 后，设计器通过 bundle URL 加载即可生效；设计器无需内置/再产物料。

## 二（续）、经验总结：MpTags 迁移全流程（代表性案例）

> **MpTags** 同时踩中「业务组件设计态」「manifest / 出码」「v-model state」「Ionic 画布桩 DOM 与全局样式」「运行态布局语义」等多条链路，迭代次数多，适合作为**标准对照**：后续类似「内部用 mr-segment / 列表可配置 / 需 v-model」的 MP 组件可复用本节检查清单。

### A. 架构原则（再次强调）

-   **物料只从主工程产出**：`lowcode-materials` 构建 bundle，设计器只加载 URL；**禁止**在设计器工程内造内置物料 JSON/JS 顶替主工程产物。
-   **不要为了设计态去改运行态业务源码**：`src/components/base/mp-tags.vue` 的 props/行为以主工程业务为准；画布差异用 **`design-components/*-designer.vue`** + **entry 指向 designer 版** 解决。

### B. 主工程物料（manifest + entry）

1. **`entries/mp-tags.js`**  
   导出 **`MpTags` = `design-components/mp-tags-designer.vue`**（与 `mp-image` / `mp-input` 同模式），画布走设计时实现，出码仍对应页面里的 `mp-tags` 标签（由引擎按物料名映射，以你们当前 bundle 协议为准）。

2. **`manifest.json`（MpTags）**  
   - **`snippetSchema`**：`list` 用 **`JSExpression`**（数组字面量），避免出码丢选项；`modelValue` 用 **`JSExpression`** 绑定 `this.state.mpTagsN`（或占位名），属性面板才显示 **Bound**，而不是写死 `"1"`。  
   - **`list`**：`schemaExtra` 里用 **CodeConfigurator**，`language: "javascript"` + **`dataType: "JSExpression"`**，兼容单引号/非严格 JSON 的编辑习惯；面板文案建议用 **List** 等清晰命名。  
   - **`modelValue`**：同样 **`JSExpression`**，与 `mr-radio-group` 等「Group 类 v-model」一致。  
   - **events**：声明 `onUpdate:modelValue` / `change` / `click` 等与运行态一致，便于事件面板绑定。  
   - 修改 manifest 后必须 **`pnpm run build:designer-materials`**，设计器加载**新 bundle** 后再测（否则面板与 snippet 仍是旧逻辑）。

3. **设计时组件 `mp-tags-designer.vue`**  
   - **解析 `list`**：`string`（JSON 或 JS 字面量）与 `array` 都要支持；`JSON.parse` 失败时用 **受控的 `new Function('return ('+s+')')()`** 仅作设计态兜底（与 CodeConfigurator 输出形态对齐）。  
   - **内部仍用 `MrSegment` / `MrSegmentButton`**（来自 `@local/mr-components`），与主工程结构一致，避免再造一套交互。

### C. 设计器：state 与拖拽落盘（易错点）

-   **左侧 State 面板的数据来自页面根 `schema.state`**。与 **`MrSwitch` / `MrRadioGroup` 相同**：拖拽时自动创建 `state.xxx` 并绑定 `modelValue` 的逻辑在 **`designer-demo/src/components/canvas/container/src/container.ts`** 的 **`onMouseUp`** 分支（外部拖入、`!sourceId`、合并 `generateNode` 默认 props 之后），**不是**只在 `useMaterial.ts` 的 `generateNode` 里写就能保证「一拖就有 state」。  
-   **MpTags** 需在 **`container.ts`** 增加与上述组件同构的分支：`updateSchema({ state })` 写入 **`mpTags1`…`**，并把节点上 **`modelValue`** 设为 **`{ type: 'JSExpression', value: 'this.state.mpTagsN', model: true }`**。  
-   **`useMaterial.ts` 的 `patchSchemaWithMaterialDefaults`** 可作为保存/预览前的**兜底**（补 state、纠绑定），但**不能替代**拖拽落盘时写入 state 的体验。

### D. 画布视觉：桩 ≠ ion-segment（易错点）

画布上的 **`MrSegment` / `MrSegmentButton` 来自 Ionic 画布桩**（如 `mr-segment-canvas.vue`），DOM 是 **`.mr-segment-stub` / `.mr-segment-button-stub`**，配套 **`mr-segment-stub-styles.js`** 与 **`injectDynamicCheckedStyle`** 的 **`::after` 下划线选中**，表现接近 **MD 分段**，与运行态 **`mp-tags.vue` 里真 `ion-segment` + module SCSS 胶囊** 不是同一套节点。

因此：

| 做法 | 结论 |
| ---- | ---- |
| 在 `mp-tags-designer.vue` 里 `:deep(ion-segment)`、`::part(native)` | **画布上不生效**，易误判为「样式改不动」 |
| 用 `:deep(.mr-segment-stub)`、`:deep(.mr-segment-button-stub)` 覆盖 | **正确方向**：胶囊圆角、边框、选中填充应对齐 `mp-tags.vue` 中变量（如 `--mr-color-button-bg-primary`、`--mr-color-button-border-tertiary`） |
| 去掉桩的下划线 | 覆盖 **`::after`**，并隐藏 **`.segment-button-indicator`**；必要时用 **`!important`** 压过动态注入样式 |
| 子项被拉成三等分 | 桩默认 **`flex: 1 1 0`**，需改为 **`flex: 0 0 auto`** 才像「多个标签」 |
| 选中态 CSS | 桩带子节点时，动态 CSS 按 **`data-segment-value` / `data-value`** 配对；建议在按钮上用 Vue **`:class="{ 'segment-button-checked': ... }"`** 与 **`effectiveValue`** 对齐，选中样式才稳定 |

详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md) 中 **MrSegment / 画布 vs 出码** 小节。

### E. 设计态布局：不要照搬运行态负 margin

运行态 **`mp-tags.vue`** 使用 **`margin-left/right: calc(-1 * var(--mp-horizontal-padding))`** 抵消页面内容区内边距，让 segment **视觉顶满屏宽**。在设计器里节点选中框按**布局盒**计算，负 margin 会把 **`MpTags` 整节点向左拽出父级**，出现**选中边框左缘溢出画布**，而 **`MpCard` 等无负 margin 的组件正常**。

-   **设计态 `mp-tags-designer` 根容器**：不要使用这对负 margin；水平方向保持 **`max-width: 100%` + `box-sizing: border-box`**。  
-   **运行态**仍保持主工程 `mp-tags.vue` 原逻辑，无需为设计器删减。

### F. 设计态垂直居中

根节点若仅设 **`min-height: 44px`** 且 **`display: block`**，内部 segment 会**贴顶**，选中框内下方留白。改为根容器 **`display: flex; flex-direction: column; justify-content: center; align-items: stretch`**，在保持**子级全宽**的前提下把标签行**垂直居中**。

### G. 依赖缺失（历史问题）

若拖到画布**不显示或报错**，先查 **`mr-components.js` 是否导出 `MrSegment` / `MrSegmentButton` / `MrLabel`**，bundle 是否包含对应物料条；桩实现与样式注入仍见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md)。

## 二（续）、经验总结：MrSegment 属性与出码

### 现象与规则

| 要点                                  | 说明                                                                                                                                                 |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **value 即 v-model**                  | MrSegment 的 value 对应主工程 v-model，物料 events 需配置 `onUpdate:value`。                                                                         |
| **子按钮 value 唯一**                 | 每个 MrSegmentButton 的 value 不能重复，否则出码后会出现多个按钮同时选中。                                                                           |
| **MrSegmentButton 不设 defaultValue** | manifest 中 MrSegmentButton 的 value 不要设 defaultValue，避免覆盖 snippet 中的默认值。                                                              |
| **出码前 value 修正**                 | 在 `patchSchemaWithMaterialDefaults` 中为 MrSegment 子按钮做 value 唯一性修正（重复或空时按 default、segment、button、tab1… 分配）。                 |
| **画布 value 同步**                   | 属性面板修改 value 后，画布桩可能不实时同步选中态（已知限制）；出码和预览不受影响。                                                                  |
| **子按钮 component-base-style 对齐**  | MrSegmentButton 是 ion-segment 的 flex 子项，`component-base-style` 的 margin 会破坏对齐；在 `constants.ts` 配置 `COMPONENTS_SKIP_BASE_STYLE` 解决。 |
| **最低要求**                          | 属性可配置 + 出码正确；画布实时同步为可选优化。                                                                                                      |

### 正确做法

1. **manifest**：MrSegment 保留 value、scrollable、disabled、mode；value 的 defaultValue 为 `"default"`；events 含 `onUpdate:value` 和 `onIonChange`。
2. **MrSegmentButton**：value 不设 defaultValue；snippet 中为每个按钮显式指定唯一 value。
3. **useMaterial**：在 `patchSchemaWithMaterialDefaults` 中检测 MrSegment 子按钮，对重复或空 value 做自动修正。

## 三、后续执行说明

-   新增或接入 **MR 原子组件**时：在 mr 统一入口按主工程 resolver 从 Vant/Ionic re-export，在 bundle 的 components 中增加对应物料条；**不**为原子增加 -designer 桩。
-   新增或接入 **MP 业务组件**时：优先用主工程源码；仅当无法在画布正常表现时再做设计时桩，并尽量用通用脚本降低维护成本。
-   遇到**画布不显示**时：先核对是否满足「设计器已引入对应第三方库 + 画布已注入脚本与样式」「mr 入口导出与主工程一致」；再参考本文「经验总结」与《业务与原子组件导入方案》中的排查表。
-   遇到 **MrSegment 出码多选**时：检查子按钮 value 是否重复，确认 `patchSchemaWithMaterialDefaults` 已对 MrSegment 做 value 唯一性修正；画布不实时同步 value 属已知限制，以出码为准。
-   遇到 **MpTags 属性面板 Bound 但 State 无 `mpTagsN`、或画布样式像 MD 下划线/选中框左溢出**时：先查 **`container.ts` 拖拽落盘**是否已为 `MpTags` 写入 state；再查 **`mp-tags-designer.vue`** 是否按 **`.mr-segment-stub`** 写样式且未使用运行态负 margin。完整对照见上文 **「MpTags 迁移全流程」**。
-   遇到 **MrLabel 运行时不显示**时：ion-label 使用 slot 显示内容，manifest 需配置 `property: "children"` + InputConfigurator，并设置 snippetSchema 默认 children；详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md) 2.6 节。
-   遇到 **MrLabel / MrButton / MrToggle 画布有字、保存 JSON 也有 `children` 字符串，但属性面板 Text 为空或回退默认值**时：这是 **`mergeProps` 只读 `props`、引擎把文案写在节点顶层 `children` 字符串** 导致的设计器问题，需在 designer-demo 中在 `getProps` 前做 `children` ↔ `props.children` 同步；若冲突则以 `schema.children` 覆盖 `props.children`，确保回显一致；详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md) **2.6.1** 节。
-   遇到 **清空 MrHeader 后单独拖入 MrBackButton，Default Href 为空、画布无返回箭头或出码不显示**时：整段 snippet 会带齐子节点 `props`，单独拖入常缺 `defaultHref`；设计器在 `getProps` 前补全 `javascript:void(0)`，与保存前 `patchSchemaWithMaterialDefaults` 一致；详见 [Ionic 组件导入与桩方案](./Ionic组件导入与桩方案.md) **2.8** 节。
-   遇到 **画布颜色/尺寸与出码不一致**时：优先检查桩样式是否使用了同源主题变量（而非示意色），并核对关键尺寸与状态映射；视觉反馈类组件以“所见即所得”为刚性标准，不通过则不计入“已测试可用”。
-   遇到 **需要循环渲染但用户找不到入口**时：先引导到组件“高级”面板配置 `loop/loopArgs/key`；若属于高频循环组件，可启用默认循环模板（拖拽即注入）降低使用门槛，仍保留手工覆盖能力。
-   遇到 **组合组件拖拽后看不出交互效果**时：优先检查 snippet 是否包含完整最小结构（而非空壳），并检查 `nestingRule` 是否限制了错误父子关系。
-   遇到 **画布里 item 底色/圆角与出码不一致**时：先对齐 Ionic 变量回退链与运行态结构，再做视觉微调；不允许以“看着更美观”替代“与出码一致”。
-   **MrButton 经验**：来自 Vant，直接 re-export；slot 文本用 `children` + InputConfigurator；Select 选项（**type、size、nativeType** 等）**一律展示英文**，项目规定——**`options[].label` 不要写中文或括号说明**（例如 `nativeType` 仅 `button` / `submit` / `reset` 与 value 一致即可）。**改 `lowcode-materials/manifest.json` 后必须在主工程执行 `pnpm run build:designer-materials`**，重新生成 `dist/lowcode-materials/bundle.json`，设计器加载该产物后属性面板才会更新；若界面仍是旧文案，先核对 bundle 是否指向最新构建、必要时强刷。**表单提交语义**：在 `MrForm` 内将提交按钮设为 `nativeType` = `submit` 时，由原生 submit 触发 Vant Form 提交流程，**在 `MrForm` 上绑定 `onSubmit` 即可**，通常不必再在 `MrButton` 上单独绑 `onClick` 做提交。
-   **MpAgreementButton 经验**：组件内部用 `$t('common.xxx')` 时，若直接导出源码，画布会显示 key 而非译文（runtime 的 $t 依赖 lowcodeI18n，设计器可能无主工程 key）。**正确做法**：做 canvas 桩，在桩内 `import { t as $t } from '../vue-i18n'`，与 mp-account-input 一致；并在 canvas-stubs/vue-i18n.ts 的 FALLBACK 中补充对应 key。
-   **MpPdf 经验**：组件依赖 vue-pdf-embed（pdf.js）等重依赖时，直接导出会导致 chunk 巨大、worker 配置复杂。**正确做法**：做 canvas 桩，占位展示「PDF」即可，出码仍用主工程真实组件。画布桩可有效规避重依赖、保持物料轻量。
-   **MrInfiniteScroll 经验**：见下文「二（续）、经验总结：MrInfiniteScroll 画布占位与事件绑定」。

## 二（续）、经验总结：MrInfiniteScroll 画布占位与事件绑定

### 规则要点

| 要点                       | 说明                                                                                                                                                                                                                                                              |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **画布占位必须可见**       | 画布桩需设置 `min-height`、slot 默认内容，确保组件拖入后始终有可见占位，便于定位与调整；否则易出现「树里有、画布看不见」导致位置放错。                                                                                                                            |
| **snippet 不设事件默认值** | 若在 snippetSchema.props 中写死事件 handler（如 `onIonInfinite: { value: "(evt) => evt.target.complete()" }`），会覆盖用户在「高级」→「事件绑定」中的绑定，出码仍用 snippet 默认而非用户方法。**正确做法**：snippet 只设属性默认（如 disabled），事件由用户绑定。 |
| **事件绑定方法注释**       | 对需在 handler 内调用特定 API 的事件（如 onIonInfinite 需 `evt.target.complete()`），可在设计器 `BindEventsDialog` 的 `rewriteMethodParams` 中，当 `eventName === 'onIonInfinite'` 且为新建方法时，注入默认注释体，提醒开发者完善逻辑后调用 complete。            |
| **固定父子结构**           | 若组件用法固定（如 mr-infinite-scroll 必包 mr-infinite-scroll-content），manifest 配置 `snippetSchema.children` 包含子节点，子组件设 `hiddenInPanel: true`，拖入即带完整结构。                                                                                    |

### 正确做法

1. **画布桩**：`mr-infinite-scroll-canvas.vue` 使用 `min-height`、`<slot>Loading...</slot>` 默认内容；样式 `mr-infinite-scroll-stub-styles.js` 中 `.mr-infinite-scroll-stub`、`.mr-infinite-scroll-content-stub` 均设 `min-height`。
2. **manifest**：snippetSchema.props 仅含 `disabled: false`，不含 `onIonInfinite`；schemaExtra.events 声明 `onIonInfinite`，并加 description 说明需调用 `evt.target.complete()`。
3. **设计器**：在 `designer-demo/src/settings/events/components/BindEventsDialog.vue` 的 `rewriteMethodParams` 中，当 `props.eventBinding?.eventName === 'onIonInfinite'` 且 `!method` 时，defaultBody 使用带注释的函数体。
