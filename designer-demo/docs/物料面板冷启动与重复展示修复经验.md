## 1. 现象回顾

在 VSCode **Extension Development Host** 中打开设计器时曾出现：

1. 画布先红块「区块 MpPage / MpDialog / … 加载错误」，过一会儿又正常。
2. Materials 面板除主工程（原子组件 / 业务组件）外，其余分组出现 **2 倍甚至 3 倍**。
3. 时间线：画布仍报错时快速打开面板 → **一倍**；主工程加载完成后 → 面板再 **翻倍**。

说明：**不是 mock 配置写了两套物料**，而是**同一批物料被多次写入 panel store**，或**渲染层在错误 key / deep watch 下把一份数据画成多份**。

---

## 2. 根因分层（按优先级）

### 2.1 加载链路竞态（导致 2x / 主工程晚到）

| 因素                        | 说明                                                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 多入口                      | `materialStartupLoader`（forceLoad）、`useResource.fetchResource` → `initMaterial` + `fetchMaterial`、资源刷新等，都可能 `addMaterials`                                   |
| `getMetaApi` 阉割           | TinyEngine 可能丢掉非标准 API；曾用 `getMetaApi().runExclusiveColdStart` → 控制台 **`runExclusiveColdStart unavailable` ×N** → fallback 只 forceLoad、**不清空** → 叠加载 |
| 相对路径 mock               | webview 里 `fetch('/mock/bundle.json')` 易空 body；需绝对化到设计器 origin（如 `http://localhost:8090/mock/bundle.json`）                                                 |
| `initMaterial` 不受门闩约束 | 即使 `fetchMaterial` 等待 ownership，`fetchResource` 仍会先 `initMaterial`，与 exclusive forceLoad 叠写                                                                   |

### 2.2 模块双实例（clear 与 add 打到不同 state）

Vite 可能对同一文件走出 **alias / 相对路径两套模块实例**。  
表现：`clear` 清了 A，`addMaterials` 写了 B；或 `hasMainProject: false` 读的是空面板，而 UI 读的是另一份。

**对策**：物料 store / session lock 挂到 `globalThis` 单例（见 §4）。

### 2.3 面板渲染层（在分组数已正确时仍「看起来三倍」）

当日志已是 `panelGroups: 14`（合并后分组数合理），但 UI 仍三倍时，重点查渲染：

| 问题                                           | 影响                                                                                |
| ---------------------------------------------- | ----------------------------------------------------------------------------------- |
| `:key="child.component"`                       | mock/html 等只有 `snippetName`，`component` 为 `undefined` → 重复 key               |
| `:key="item.group"`                            | 同名 group 多条时 collapse 复用异常                                                 |
| `getComponentName` 渲染期写 `child.name.en_US` | 触发 `deep: true` watch → 反复同步 `state.components` → 与坏 key 叠加放大「多倍感」 |

## 3. 成功验收时的日志画像（MaterialsDiag）

过滤控制台：`MaterialsDiag`（VSCode 下 `logFilter` 已放行该前缀；可用 `localStorage.TINY_MATERIALS_DEBUG='0'` 关闭诊断）。

**健康序列（节选）：**

```
startupOwnership: claimed
startup: begin                    { isVsCodeEnv, hasHttpBundles, bundleUrls: [主工程, mock] }
startup: path=exclusiveColdStart(forceLoad)
runExclusiveColdStart: clear + load once
forceLoad: start → each url 200 → forceLoad: done { loaded: 2 }
startup: forceLoad inside exclusive { forceLoadOk: true, panelGroups: 14 }
runExclusiveColdStart: done {
  hasMainProject: true,
  htmlChildCount: …,
  htmlKeys: …
}
startupOwnership: released
startup: path=exclusiveColdStart done
```

**判定表：**

| 字段                                      | 期望            | 含义                                                           |
| ----------------------------------------- | --------------- | -------------------------------------------------------------- |
| `unavailable` / `fallback forceLoad only` | **不应再出现**  | exclusive 必须走通，不能只 forceLoad 不清空                    |
| `loaded`                                  | `2`（当前配置） | 主工程 HTTP + mock 各一次                                      |
| `hasMainProject`                          | `true`          | 面板含「原子组件 / 业务组件」或 Mp/Mr snippet                  |
| `panelGroups`                             | ≈ `14`          | builtin + mock + 主工程合并后的分组数（layout/basic 等会合并） |
| UI                                        | 各组一份        | Form / html / Layout 等无肉眼重复                              |

**已知偏差（隐患，见 §6）：** 验收通过时曾出现 `htmlChildCount: 6`（理想为 mock 的 `3`：`h1/p/video`）。  
UI 因展示层 `dedupeSnippetGroups` 仍显示一份；**store 内 html 可能仍有 2 份 children**。属隐藏数据层问题，**改前需评估**。

## 4. 已落地的稳定手段（代码地图）

| 机制                     | 位置                                                 | 作用                                                                                                  |
| ------------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Session lock + ownership | `src/composable/materialsSession.ts`                 | `claim/release`、`runExclusiveColdStart`、`isMaterialsWriteBlocked`；**直接 import，不经 getMetaApi** |
| globalThis 单例          | `useMaterial.ts` / `materialsSession.ts`             | 避免双实例 clear/add 分裂                                                                             |
| 冷启动唯一写路径         | `src/composable/materialStartupLoader.ts`            | VSCode + HTTP：`clear → initMaterial → forceLoad(绝对 URL)`；再 `fetchResource`（物料应 skip）        |
| 写拦截                   | `useMaterial.addMaterials` / `initMaterial`          | ownership 或 session ready 时，非 exclusive 写入直接 blocked                                          |
| 绝对 URL                 | `materialStartupLoader.toAbsoluteBundleUrl`          | mock 相对路径 → 设计器 origin                                                                         |
| 面板 key / watch         | `meta/component/src/Main.vue`                        | 唯一 key；禁止渲染期 mutation；浅层 watch；computed 再 dedupe                                         |
| 诊断                     | `src/composable/materialsDiag.ts` + `logFilter` 放行 | 可复现验收                                                                                            |

**物料 URL 来源（有意双源，不是 bug）：**

-   `engine.config.js` → `/mock/bundle.json` + `VITE_MATERIAL_BUNDLE_URLS`
-   `getBundleUrls()` 再合并 window / env，HTTP 优先

主工程只在远程 bundle，mock/builtin 负责官方示例分组；**重复来自多次 add，不是「配置了两个 URL」本身**。

## 5. 经验法则（以后改加载时遵守）

1. **互斥 API 不要只挂在 getMetaApi 上**——自定义方法可能被剥掉；session 用直接 import + `globalThis`。
2. **clear 与 add 必须打同一 store**——先怀疑双实例，再怀疑竞态。
3. **ownership 要挡住 `initMaterial`，不只挡住 `fetchMaterial`**。
4. **forceLoad 后不要再无条件 forceLoad**；session ready 后二次 `addMaterials` 一律视为回归。
5. **面板列表 key 必须用 `snippetName \|\| component \|\| index`**，不要只用 `component`。
6. **禁止在 render 路径写物料 reactive 字段**（如临时补 `en_US`）。
7. **排障先看 MaterialsDiag 时间线**，再改合并算法；分组数对、UI 仍多倍 → 先查渲染。

## 6. 隐藏隐患与「是否再改」评估入口

> 本节只做记录与评估维度；**未授权前不要为「消灭 htmlChildCount: 6」大改加载链路。**

### 6.1 Store 内 html children 可能仍为 2×

-   **现象**：`htmlChildCount: 6`，UI 仍正常（展示层 dedupe）。
-   **风险**：后续若去掉面板 dedupe、或其它逻辑按 `materialState.components` 做导出/统计，会拿到偏大列表；理论上 merge 边界情况仍可能再现。
-   **可能原因（待证）**：同一次 cold start 内某路径对 mock 片段写入两次；或 dedupe 键在写入瞬间不一致等。
-   **建议验证**：在 `runExclusiveColdStart: done` 展开 `htmlKeys`；在 `addMaterials: after` 看 html 的 `count` 是否从 3→6。
-   **改动评估（若要修）**：

| 项     | 粗估                                                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------------------------- |
| 改动量 | 小～中：加强 `addComponentSnippets` / exclusive 结束强制 `materialState.components = dedupe(...)`；必要时打点定位第二次写入 |
| 影响面 | 物料面板、冷启动、refreshMaterial；回归：mock 分组、主工程 Mp/Mr、画布拖拽                                                  |
| 收益   | store 与 UI 一致，去掉对展示层 dedupe 的依赖                                                                                |
| 建议   | **可排期小修复**；非紧急                                                                                                    |

### 6.2 globalThis 单例跨 webview 复用

-   **风险**：webview 若未销毁就二次打开设计器，旧 store 残留（正常 exclusive clear 可清；clear 失败时会叠）。
-   **改动评估**：中——改为「每次 designer mount reset」或弱化 globalThis；需测 HMR / Reload Host。
-   **建议**：观察；仅在「不 Reload 连续开页仍翻倍」时再动。

### 6.3 诊断日志默认开启

-   **现状**：`MaterialsDiag` 默认开，`logFilter` 白名单放行。
-   **风险**：控制台噪音；生产向 webview 略吵。
-   **改动评估**：小——默认关或仅 VSCode + debug flag。
-   **建议**：稳定一阶段后可改为默认关。

### 6.4 不建议轻易回退的方向

-   去掉 forceLoad、只靠 `fetchMaterial`（曾导致主工程 Mp 丢失）。
-   用「永久 `hasFetchedBundleMaterials`」堵第二次加载（易挡晚到的 HTTP URL）。
-   再经 getMetaApi 暴露 exclusive API 作为唯一入口。

## 7. 最小回归清单

每次改 `materialStartupLoader` / `materialsSession` / `useMaterial` / Materials `Main.vue` 后：

1. Reload Extension Host，打开带主工程页面的设计器。
2. Console 过滤 `MaterialsDiag`：无 `unavailable`；`loaded: 2`；`hasMainProject: true`。
3. 面板：Layout / Basic / html / Form / **原子组件·业务组件** 均为一份。
4. 画布：Mp 容器不再持久红块（允许极短闪错）。
5. （可选）记录 `htmlChildCount`；目标长期为 `3`。
